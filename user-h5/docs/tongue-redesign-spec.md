## 三、接口字段 → 渲染器映射

后端在第三方报告之上补齐了视图字段（`user-service`）：

| 后端字段                        | 含义                                                                                     | 小程序渲染器                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `reportGroups[].tabKey`         | 一级标题 → `overview/diet/acupoint/emotion/sport/other`                                  | 固定五 Tab；`other` 追加为额外 Tab（内容不丢）                                       |
| `sections[].parentId`           | 父节点 id（顶层为 null）                                                                 | 前端还原层级，支撑「周X / 节气」pill 与子块                                          |
| `sections[].block`              | `TEXT/DESCRIPTIONS/ANALYSIS/MEDIA_AUDIO/MEDIA_VIDEO/MEDIA_IMAGE/MEDIA_DETAIL/TITLE_ONLY` | 选择内容块渲染器；未识别值走通用兜底                                                 |
| `sections[].analysis.factor`    | 舌象特征（舌色/苔色/舌形/苔质/津液）                                                     | 两列文本格（图5）                                                                    |
| `sections[].analysis.feature`   | 舌象指数（5 项 + difference）                                                            | 3+2 网格，仅显示 `tongueVal`（差值与参考图一致地不展示）                             |
| `sections[].descriptions`       | `【标题】+ 内容` 成对块                                                                  | 描述块；标题命中「易发疾病 / 常见体征」时渲染为标签云                                |
| `sections[].media`              | 音频 / 视频 / 图片 + 可选 `duration`                                                     | 音频行、视频海报卡（有 `duration` 才显示角标）                                       |
| `products[].matched` + 商城字段 | 报告商品名 → 商城商品（图/价/标签/适宜体质）                                             | 命中 → 商城卡（图 + 名称 + 标签 + 适宜体质 + 价格）；未命中 → 该商品不渲染（含标题） |

## 六、本轮修复记录（内容与数据）

起因：详情页出现 `<p>`/`&nbsp;` 文字、饮食 Tab 空、记录与详情头部信息与当次检测不一致。

| 问题                    | 根因                                                                                    | 修复                                                                                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<p>` / `&nbsp;` 泄漏   | 第三方 `content` 原样下发，详情页对「描述块 / 推荐理由」用 `<text>` 渲染（不解析 HTML） | 后端统一清洗：正文走白名单 HTML（p/br/strong/em/u/ul/ol/li/span，去属性、解实体、转义裸 `&<>`），描述/推荐理由/摘要转纯文本；前端再加一层纯文本兜底 |
| 饮食 Tab 空             | 推荐商品被限定「商城名称匹配成功才渲染」，未命中即整块消失；Tab 也没有空态              | 商品卡改两态（命中→商城卡，未命中→文字卡保留名称+推荐理由）；每个 Tab 增加「内容暂未生成」空态                                                      |
| Tab 归组不稳            | `tabKey` 只做标题等值匹配，出现「饮食调理」这类标题时固定 Tab 会空、内容被挤到额外 Tab  | `tabKey` 改关键字包含匹配（概况/饮食/穴位/经络/情志/心理/运动/健身），未知标题仍走 `other` 额外 Tab                                                 |
| 性别·年龄与当次检测不符 | 接口未下发 `sex`/`age`，前端只能用本地资料顶替                                          | `TongueReportSummaryResponse` / `TongueReportDetailResponse` 新增 `sex`/`age`；前端优先用接口值，老记录才回落本地资料                               |

回归用例：`TongueReportParserTest`（清洗 + tabKey 容错）、`TongueReportServiceTest`（下发 sex/age、老数据为 null）、`scripts/tongue-detection.test.mjs`（纯文本字段、空态、商品两态、头部取值优先级）。

## 七、真实报文核对结论（2026-10-16 抓取 · 湿热质）

用线上账号（记录 id=2，`reportStatus=READY`）实际拉取 `/api/v1/app/tongue/reports/{id}` 核对，结论如下。

| 事实                                                                             | 影响与处理                                                                                                                                        |
| -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 五个一级分组：概况 / 饮食 / 穴位 / 情志 / 运动                                   | 与参考图的五个 Tab 完全同源                                                                                                                       |
| **饮食分组只有 5 条推荐商品，没有任何章节**                                      | 参考图 6 的「饮食方式 / 养生饮茶 / 四季节气进补 / 一周食谱」在当前供应商数据里**不存在**；按「以第三方为准」渲染推荐商品卡（未命中商城 → 文字卡） |
| 推荐商品只给名称 + 推荐理由，**无缩略图、无价格**                                | 养生饮茶卡片只能是文字卡；商城同名商品命中时才升级为图片+价格卡                                                                                   |
| 穴位：3.1 调理方式 + 3.2 穴位操作（阴陵泉穴 / 三阴交穴，含视频与定位·手法·功效） | 走「媒体+描述」卡片渲染                                                                                                                           |
| 情志：4.1 调理方式 + 4.2 调体音乐（2 首音频）+ 4.3 呼吸冥想（2 个视频）          | 音频行走 `InnerAudioContext`，视频走海报卡                                                                                                        |
| 运动：5.1 调理方式 + 5.2 中医健身功法（八段锦 / 六字诀 / 明目功，均视频）        | 走视频卡渲染                                                                                                                                      |
| 脏数据形态：`<p style>`、`<font face>`、`&nbsp;`、`<b>`、`<br>`                  | 正文白名单清洗保留 `<p>/<br>`，描述与推荐理由转纯文本                                                                                             |
| 媒体节点**没有时长字段**                                                         | 播放卡不显示时长角标（有字段时才显示）                                                                                                            |
| 线上接口**未下发** `tabKey` / `parentId` / `block`                               | 前端按标题关键字兜底归组（`tabKeyOfTitle`）；后端部署后由接口下发，两条路径都已覆盖                                                               |
