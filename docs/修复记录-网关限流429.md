# 修复记录-网关限流 429 误伤

> 日期：2026-09-29 ｜ 分支：dev/dev-20260928 ｜ 影响面：gateway（仅限流逻辑与配置）

## 一、问题现象

小程序/网关侧偶发大面积 `429 Too Many Requests`，正常用户在高频轮询（门店排队、订单状态）时被连带误伤。

## 二、根因定位

### 1. Redis 写入的 db/key（已彻底确认）

| 项目    | 修复前                                                                       | 修复后                                                   |
| ------- | ---------------------------------------------------------------------------- | -------------------------------------------------------- |
| **db**  | `db0`（`spring.data.redis` 未配 `database`，默认落 db0，与 AUTH 登录态混库） | **`db4`**（独立限流库，可用 `RATE_LIMIT_REDIS_DB` 覆盖） |
| **key** | `wuling:ratelimit:{ip}`（纯 IP 维度）                                        | `wuling:ratelimit:{路径分组}:{ip}`（IP + 路径分组）      |

> 原 key 前缀 `wuling:ratelimit:` 游离在 `RedisNamespace`（AUTH/SMS/CACHE/BIZ）体系之外，既无库号映射，也无业务维度，排查时无法按命名空间隔离清理。

### 2. 429 误伤的两个叠加因素

1. **纯 IP 维度 + 固定 200 QPS / 1s 窗口**：小程序经 Nginx 后出口 IP 收敛，大量真实用户共享同一 IP，1 秒内超过 200 次即整段 429，正常用户被连带误伤。
2. **filter 顺序隐患**：`RateLimitGlobalFilter.getOrder()` 原为 `-100`，与 `GatewayLogFilter` 完全相同，GlobalFilter 同序执行顺序不确定。

## 三、改动清单

### 1. `gateway/.../filter/RateLimitGlobalFilter.java`（重写，原文件名 RateLimitConfig.java）

- 限流专用 `ReactiveStringRedisTemplate` 显式 `SELECT db4`，与业务 db0–db3 隔离。
- 新增三处关键日志：
  - 创建独立连接时打印 `database`；
  - filter 初始化打印 `database / keyPrefix / qps / window`；
  - **429 判定时打印完整上下文**（`database / key / ip / path / count / qps`）。
- 限流维度从「纯 IP」升级为「路径分组 + IP」（`pathGroup()` 取路径第一段），解决单 IP 高频访问不同接口被总闸误伤。
- `getOrder()` 从 `-100` 改为 `-60`，与 `GatewayLogFilter(-100)` 错开，消除同序不确定。

### 2. `gateway/.../application.yml`

新增配置项：

```yaml
app:
  rate-limit:
    redis-db: ${RATE_LIMIT_REDIS_DB:4}
```

## 四、定位 429 的操作方法

启动日志：

```
[限流] Redis 独立连接已创建 database=4
[限流] 初始化完成 database=4 keyPrefix=wuling:ratelimit: qps=200 window=1s
```

复现 429 时：

```
[限流] 触发 429 database=4 key=wuling:ratelimit:api:1.2.3.4 ip=1.2.3.4 path=/api/v1/... count=201 qps=200
```

直接定位 Redis：

```bash
redis-cli -n 4 KEYS 'wuling:ratelimit:*'           # 查看 db4 限流 key
redis-cli -n 4 TTL  'wuling:ratelimit:api:1.2.3.4' # 窗口剩余时间
redis-cli -n 4 DEL  'wuling:ratelimit:api:1.2.3.4' # 手动解除某 IP 限流
```
