# 调整方案：储值支付「订单不存在」+ 支付后跳转成功页 + 购物车清空

> 日期：2026-09-27
> 现象：储值支付提交订单后详情页弹出「订单不存在」；期望跳「支付成功页」并可跳订单列表；从购物车去结算支付完成后购物车商品没清空
> 状态：✅ 已实施（2026-09-28）

---

## 一、根因分析

### 1.1 「订单不存在」的根因：详情页 URL 参数名与页面读取不一致

`pages/order-confirm/order-confirm.js` 支付成功后跳转：

```js
// 储值支付（submitWithStoredValue）
wx.navigateTo({ url: '/pages/order-detail/order-detail?orderNo=' + paid.orderNo });
// 微信支付（createOrderAndPay）同样是 ?orderNo=
```

而详情页只读 `options.id`：

```js
// pages/order-detail/order-detail.js
onLoad(options) {
  const orderId = options && options.id ? options.id : '';   // 读的是 id
  ...
  fetchOrderFromRemote(orderId).then(order => {
    if (!order) { wx.showToast({ title: '订单不存在' }); ... }
  });
}
```

传的是 `orderNo`，读的是 `id`，于是 `orderId` 恒为空串，`getOrderById('')` 返回 null，
`fetchOrderFromRemote('')` 里 `resolveOrderNo(null, '')` 也返回空串，
函数直接 `Promise.resolve(null)`，页面据此提示「订单不存在」并返回。

这解释了截图现象：页面骨架已渲染（本地镜像为空时 `order` 为 `{}`），
状态卡、金额区全是空白，随后弹出「订单不存在」。

**同时暴露的第二处放大问题**：`fetchOrderFromRemote` 在拿不到订单号时直接返回 null，
不再尝试任何远端查询；`fetchOrderDetail(orderNo)` 本身按订单号精确匹配，
与「列表用主键 id、分享/通知用订单号」两种入口始终存在错配风险。

### 1.2 购物车未清空的根因：没有任何清空动作

- `pages/menu/menu.js` 的 `handleCheckout` 把选中商品塞进 `globalData.pendingOrder` 后
  跳转确认页，**购物车仍在 `menu.data.cartItems` 中**；
- `pages/order-confirm/order-confirm.js` 支付成功后只更新了 `globalData.pendingOrder`，
  **没有回调点单页清空购物车**；
- 点单页 `onShow` 只重拉菜单与门店（`refreshThenSync()`），购物车项按商品重新标注上下架，
  **不会因为「已下单」而移除**。

微信支付与储值支付两条链路都缺这一步，所以从购物车结算后商品一直留着。

### 1.3 「支付成功页」当前不存在

`app.json.pages` 中没有支付成功页，确认页支付后一律 `navigateTo` 到详情页。
期望的「支付成功 → 跳订单列表」需要新增一个页面。

## 二、调整方案

### P0（必改）：修复详情页订单不存在

**改动点 1 — 详情页参数兼容 `id` 与 `orderNo`**

`pages/order-detail/order-detail.js` 的 `onLoad`：

```js
onLoad(options) {
  const opts = options || {};
  // 兼容两种入口：列表/详情用主键 id，下单成功后跳转用 orderNo
  const orderId = opts.id || opts.orderNo || '';
  this.setData({ orderId });
  ...
}
```

**改动点 2 — 明确 `resolveOrderNo` 的兜底语义**

`utils/orders.js` 现有一条「纯数字视为主键、不当作订单号」的规则：

```js
// 纯数字视为数据库主键，不当作订单号（订单号一定带业务前缀，如 WX / GC）
if (!raw || /^\d+$/.test(raw)) return '';
```

该规则本身正确（订单号确实带 `WX` 前缀），保持不动；
仅需在测试中固化「本地镜像为空 + 入参为带前缀订单号 → 直接用该入参查远端」这一行为。

**改动点 3 — 单测固化 URL 契约**

新增 `scripts/order-detail-param.test.mjs`：
读取 `pages/order-confirm/order-confirm.js`，断言其跳转 URL 携带 `orderNo`；
读取 `pages/order-detail/order-detail.js`，断言 `onLoad` 同时解析 `options.orderNo` 与 `options.id`。
（两次笔误的根因都是「没有契约测试」，用测试锁死。）

### P1（必改）：新增支付成功页并作为支付后落点

**新增页面 `pages/pay-success/pay-success`**（4 个文件），加入 `app.json.pages`，
同步更新 `scripts/check-project.mjs` 的 `expectedPages`（否则 `npm run check` 会失败）。

结构与设计约束（依据 `user-h5/docs/design-system.md`）：

| 项       | 取值                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 页面骨架 | 模式 B「三段式固定型」：`navigation-bar`（标题「支付结果」）+ `scroll-view`  |
| 状态图标 | `/assets/icons/lucide/circle-check-big.svg`（Lucide 已有，无需新增映射）     |
| 主文案   | `--font-xl` + `--brand-green`，「支付成功」                                  |
| 副文案   | `--font-base` + `--text-secondary`，「订单已提交，请留意取餐提醒」           |
| 订单号   | 卡片行展示，右侧复制入口复用 `copy.svg`                                      |
| 金额     | `--font-xl` + `--price-red`，由服务端 `paidAmount` 换算为元                  |
| 主按钮   | 「查看订单」，`--brand-green` 底 + `#FFFFFF` 字，高 `80rpx`                  |
| 次按钮   | 「返回首页」，描边款，高 `80rpx`                                             |
| 间距     | 仅用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 40rpx`，页面左右 `var(--page-gutter)` |
| 单位     | 全部 rpx，禁止 px                                                            |

交互：

- `onLoad(options)` 读 `orderNo`；
- 进入页面时调 `fetchOrderDetail(orderNo)` 回读服务端订单，
  以服务端金额为准展示，避免依赖本地传参被篡改后误导用户；
- 「查看订单」：`wx.switchTab({ url: '/pages/orders/orders' })`
  —— 订单页是 Tab 页，**必须用 `switchTab`**，用 `navigateTo` 会静默失败（见 `utils/navigate.js` 踩坑记录）；
- 「返回首页」：`wx.switchTab({ url: '/pages/home/home' })`。

**确认页跳转改造**（`pages/order-confirm/order-confirm.js`）：

| 函数                      | 现状                | 改为                |
| ------------------------- | ------------------- | ------------------- |
| `createOrderAndPay()`     | `navigateTo` 详情页 | `redirectTo` 成功页 |
| `submitWithStoredValue()` | `navigateTo` 详情页 | `redirectTo` 成功页 |

用 `redirectTo` 而非 `navigateTo`：确认页不应留在返回栈里，
用户从成功页返回时不应回到「提交支付」页重复下单。

### P1（必改）：支付成功后清空购物车

**清空的边界**（重要，避免误删）：

- 只清「本次进入结算的商品」；
- 立即购买（`handleSpecBuy`）走独立 `pendingOrder`，**不清购物车**；
- 部分选中结算时，只移除已结算条目，未选中商品保留。

**实现方式（跨页通信）**：

1. `pages/menu/menu.js` 标记来源：

```js
// handleCheckout 内
getApp().globalData.pendingOrder = {
  items: selectedItems,
  storeId: this.data.currentStore.id,
  orderMode: this.data.orderMode,
  fromCart: true              // 新增：来源为购物车结算
};

// handleSpecBuy 内
getApp().globalData.pendingOrder = {
  items: [ ... ],
  storeId: this.data.currentStore.id,
  orderMode: this.data.orderMode,
  fromCart: false             // 新增：立即购买，不动购物车
};
```

2. `utils/cart.js` 新增纯函数（便于单测）：

```js
/** 从购物车中移除本次已结算的条目（按条目 id 匹配，保留其余商品）。 */
function removeCartItems(cartItems, settledIds) {
  const items = Array.isArray(cartItems) ? cartItems : [];
  const ids = new Set((settledIds || []).map(String));
  if (!ids.size) return items.map(item => Object.assign({}, item));
  return items.filter(item => !ids.has(String(item.id))).map(item => Object.assign({}, item));
}
```

3. 确认页支付成功后写入一次性标记（**必须在成功分支内**，失败分支不得写入）：

```js
const app = getApp();
const pending = app.globalData.pendingOrder || {};
if (pending.fromCart) {
  app.globalData.settledCartIds = (pending.items || []).map(item => item.id);
}
```

4. 点单页 `onShow` 消费标记：

```js
onShow() {
  if (this.getTabBar) this.getTabBar().setData({ selected: 1 });
  this.setTabBarHidden(false);
  this.returningFrom = '';
  this.consumeSettledCart();          // 新增：先清已结算条目
  this.refreshThenSync().then(() => this.notifyMenuLoadFailure());
},

/** 消费下单成功留下的结算标记，只移除本次已结算的条目。 */
consumeSettledCart() {
  const app = getApp();
  const settledIds = app.globalData.settledCartIds;
  if (!settledIds || !settledIds.length) return;
  app.globalData.settledCartIds = null;   // 一次性标记，先清避免重复消费
  const cartItems = removeCartItems(this.data.cartItems, settledIds);
  const summary = summarizeCart(cartItems);
  this.setData({
    cartItems,
    cartCount: summary.count,
    cartTotal: summary.total,
    cartVisible: cartItems.length > 0,
    hasUnlistedInCart: cartItems.some(item => item.selected && item.listed === false)
  });
}
```

**为什么用「标记 + onShow 消费」而不是跨页直接 `setData`**：
点单页在 `navigateTo` 后不会被销毁，直接改它的 `data` 会与页面自身的 `setData` 竞态；
聚焦点单页时消费标记，时序最稳，且天然覆盖「成功页 → 返回点单页」的路径。

### P2（建议）：其他一致性修正

| 项                 | 说明                                                                                                                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 详情页支付方式显示 | 截图里「支付方式 未支付」。`resolvePayMethodText` 优先读 `payMethod`，缺失才回落 `payStatus`；后端 `OrderDTO` 无 `payMethod`、有 `payChannel`。建议把 `payChannel` 提到第一优先级（`STORED_VALUE` → 储值余额、`WXPAY` → 微信支付） |
| 详情页加载态       | `order` 为 `{}` 时整页空白。建议远端查询返回前显示骨架/加载态，避免用户误以为丢单                                                                                                                                                  |
| 不存在提示时机     | 应在远端确认「订单不存在」后再提示并返回，避免网络抖动把正常订单判为不存在                                                                                                                                                         |

### 验证标准（全部通过才算完成）

1. `cd user-h5 && npm run check` → 项目结构校验通过（含新增页面注册）；
2. `cd user-h5 && npm run test:acceptance` → 验收通过；
3. 工具/真机手测：
   - 购物车勾选 2 件 → 去结算 → 储值支付 → **跳支付成功页**（不再提示订单不存在）；
   - 成功页「查看订单」→ 进入订单页「今日订单」，能看到刚支付的订单，状态「待核销」；
   - 成功页返回 → **不回确认页**（`redirectTo` 生效）；
   - 再次进点单页 → **已结算的 2 件商品已从购物车移除**，未勾选商品仍在；
   - 「立即购买」（不走购物车）支付成功后 → 购物车内容**不变**；
   - 支付失败（余额不足）→ 购物车**不清空**，停留确认页并提示后端文案。

### 风险点

| 风险                       | 处置                                                 |
| -------------------------- | ---------------------------------------------------- |
| 新页面未注册导致包校验失败 | 同步改 `check-project.mjs` 的 `expectedPages`        |
| Tab 页跳转静默失败         | 成功页统一用 `wx.switchTab` 跳订单页/首页            |
| 结算标记未消费导致残留     | 标记写入与消费都在成功分支；消费后立即置 null        |
| 部分选中结算误清未选中商品 | `settledCartIds` 只记录本次提交的条目 id             |
| 本地传参被篡改展示错误金额 | 成功页金额以 `fetchOrderDetail` 返回的服务端金额为准 |
