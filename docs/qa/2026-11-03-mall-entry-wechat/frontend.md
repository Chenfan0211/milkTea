日期：2026-11-03。工作目录：`E:\项目\milkTea`，沿用 `codex/mall-v96-cover-layout` checkout，保留原有未提交改动。本文只记录本轮前端修改与本地验证。

## 改动

- 商城统一按整数分格式化为固定两位小数，`1` 分显示 `0.01`；未改共享 `api.fenToYuan` 的饮品金额规则。
- 购物车校验所有商品后先写回最新库存、上下架与有效状态，只为已选且有效商品报价。未选失效商品保留在列表，已选失效商品阻断本次结算；报价失败不回填旧库存。异步校验回包检查账号与请求序号，避免换号后覆盖新账号购物车。
- 提交结算前重新校验并获取 quote，拒绝不可合并或无效报价。价格变化先刷新商品与应付金额，提示重新确认，本次不建单；下一次点击才继续。微信仍为默认支付方式，保留余额方式。校验期间换号禁止继续建单。
- 商城订单列表用请求序号与用户标识隔离旧响应、旧错误；重置加载期间阻止提前请求下一页。
- 售后总列表改为每页 20 条、滚动追加、独立的加载更多错误与重试，可访问超过 50 条的记录。指定订单售后仍走订单专用接口。
- 购物车来源订单创建后，按用户和订单号保存本次商品数量快照。首次付款、订单列表补付、订单详情补付统一消费同一快照；获取到服务端已支付订单也可恢复清理。商品和消费标记在同一 Storage 对象中写入，避免重复成功重复扣除。行标识与累计新增数量保留付款期间后加购、减少数量后再加购、删除后重新加入的商品。兼容原数组购物车缓存；立即购买不扣购物车。
- 仅补齐“我的”配置功能入口的 `aria-role` / `aria-label`。没有硬编码商城入口，没有改首页或导航；线上入口配置由主代理处理。
- 新行为测试加入 `user-h5/package.json` 的 `check` 链路；原商城订单金额预期同步为两位小数。

涉及 `user-h5/packageMall`、`user-h5/utils/mall-cart.js`、`user-h5/scripts/mall-checkout-regressions.test.mjs`、`user-h5/scripts/mall-pages.test.mjs`、`user-h5/package.json` 与 `user-h5/pages/profile/profile.wxml` 的功能入口无障碍属性。

## 独立审查后的三项修复

独立审查指出以下遗漏，已只针对这三项继续修改，没有修改共享 `login-guard.js`：

1. 真实 `requirePhone` 会把 action 拒绝误判为授权失败。商城提交的业务 action 现在内部接住 `createAndPay` 的业务错误、恢复提交状态并提示；授权后续跑也经过同一处理。改价只更新金额并等待再次点击，既不跳授权，也不留下自动重新建单动作。
2. 售后已有数据时，reset 现在始终进入 loading 并把页码重置为 1；加载更多在重置期间被锁住，第一页成功后再从第二页追加，旧请求仍由序号隔离。
3. 购物车删除确认、增减数量、单选、全选都会增加校验序号并结束旧 checking 状态；等待中的 validate / quote 回包被废弃，不能恢复已删除条目或覆盖用户刚完成的编辑。

## 限制与后续验证

- 行为测试执行真实商城页面与购物车逻辑，仅替代微信存储、网络和支付外部边界；没有启动开发者工具、调用线上 API、执行真实微信或余额资金操作，没有上传、发布或提交 Git。
- 订单清车快照存在本机当前用户 Storage；跨设备、主动清除缓存或升级前已创建而没有本地快照的订单，不推断并删除当前购物车。Storage 写入失败时不能承诺保留结算快照，但商品与消费标记同次写入，不会因分开写入而重复扣量。
- 本机缓存由旧数组升级为包含 `items` / `settlements` 的对象；当前代码已覆盖旧数组兼容，旧版本回滚的缓存兼容未验证。
- 线上“我的”入口配置、真实微信默认支付与余额支付联调、真机页面交互仍需主代理按已批准范围完成；这里的本地通过不代表线上验收通过。
