# 线上商城储值支付、退货退款、分账与团长购买测试方案

日期：2026-11-09。测试入口：微信开发者工具中的 `user-h5` 小程序；运营审核和分账核对使用现有管理后台及只读对账查询。此次只使用储值支付，不测试优惠券叠加。

## 1. 验收口径与当前阻断点

1. 普通用户购买有分销佣金的商品，列表、详情、购物车、结算、订单的成交单价应一致，均为 `SKU 售价 + 分销佣金`；团长本人购买应为 `SKU 售价`，不产生团长分佣。无分销佣金商品两种身份同价。商品价格与角色关系以服务端报价和下单快照为最终校验源。
2. 已发货或已完成订单申请退货退款：买家提交退货申请，填写退货快递公司和单号；运营核验退货物流并确认收到商品后，才能审核通过并发起储值原路退款。未收货、单号缺失、重复提交均不得退款。
3. 商城订单完成后核对平台、供应商、团长三方分账；门店、资源方、投资人为 0。退款成功后，核对原参与方的冲正、账户余额、流水和幂等性。
4. **当前代码阻断点（静态核对，尚未在开发者工具实测）：**商品列表和详情只读取基础售价，普通用户与团长的展示价没有区分；售后申请/实体/接口没有退货快递单号及商家确认收货状态；运营点击“通过”会直接调用退款。因此第 1、2 项完整验收须在对应实现到位后执行。不得以“后台填原订单发货单号”代替买家退货物流。
5. 当前部分退款按“本次退款额 / 原订单实付”的比例冲正各结算记录。混合不同供应商或不同成本、佣金的商品时，要专门核对是否符合“退哪件、冲正该件归属”的业务要求；若不符合，记录为分账缺陷，不能只凭总额守恒判通过。

## 2. 测试准备

| 项目 | 准备与记录                                                                                                                                                                                    |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 版本 | 记录开发者工具版本、小程序构建版本、API 地址、后台及服务镜像版本；确认小程序连到待验收线上环境。当前工作区有未提交改动，执行时必须锁定实际构建和服务版本。                                    |
| 账号 | 普通用户 A（有归属团长）、普通用户 B（无归属团长）、团长本人 C、运营审核账号；记录主体 ID，不把凭据写入测试报告。                                                                             |
| 商品 | 专用可控库存 SKU1：售价 10.00 元、分销佣金 2.00 元/件、供应商成本 5.00 元/件、库存至少 6 件；另备佣金 0 的 SKU2，以及不同供应商/成本的 SKU3。金额均以分为准，实际测试商品参数以后台快照为准。 |
| 资金 | 三个买家储值余额足够；记录测试前会员储值余额、平台/供应商/团长主体可用余额和流水末号。使用专用测试商品及账号，逐笔记录真实扣款和退款。                                                        |
| 物流 | 商家发货单号和买家退货单号分别准备；若要求验证“实际收到货”，使用可追踪的测试包裹及签收记录，不能只在系统里手工改状态。                                                                        |
| 取证 | 每单记录订单号、售后单号、退款单号、用户/团长/供应商主体 ID、商品及价格快照、时间、开发者工具页面与 Network、后台截图、只读数据快照。                                                         |

示例金额：SKU1 买 2 件，普通用户实付 `2 × (10 + 2) = 24` 元，团长实付 `2 × 10 = 20` 元。普通用户 A 完成后应分：供应商 10 元、团长 4 元、平台 10 元；普通用户 B 完成后：供应商 10 元、团长 0 元、平台 14 元；团长 C 自购完成后：供应商 10 元、团长 0 元、平台 10 元。此处忽略优惠券；实际对账以配置与订单快照重新计算，绝不把示例数字当成线上数据。

## 3. 微信开发者工具主流程

| 编号 | 操作                                                   | 必核结果                                                                                                                                                                            |
| ---- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M01  | A、B、C 分别登录，进入线上商城→列表→详情→切 SKU        | SKU1 普通用户显示 12 元，团长显示 10 元；SKU2 同价。登录态/切换账号后不串价。                                                                                                       |
| M02  | 各身份加购、改数量、进入结算                           | 购物车、服务端报价 `payableAmount`、页面应付、提交订单金额一致；后台改价或库存变化时重新报价并提示。                                                                                |
| M03  | 选择“储值支付”并下单；另测余额不足及待支付订单继续支付 | 支付渠道为 `STORED_VALUE`；成功只扣一次余额并生成一笔支付流水；余额不足不伪报成功；原单补付不重复建单/扣库存。                                                                      |
| M04  | 运营填商家发货公司和单号；买家查看物流并确认收货       | 订单 `PAID → SHIPPED → COMPLETED`；原发货单号可见。确认收货只触发一次分账。                                                                                                         |
| M05  | 查询订单/支付/库存及商城分账快照                       | `orders`、`order_item`、`payment`、`mall_stock_log`、`split_snapshot`、`settlement_record`、`subject_account`、`fund_flow` 与页面一致；完成前没有本单分账，完成后各方合计等于实付。 |

## 4. 退货退款与冲正

| 编号 | 操作                                                                                    | 必核结果                                                                                                             |
| ---- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| R01  | 已付款未发货的订单申请整单退款                                                          | 储值原路退回；无退货物流步骤；会员余额、库存和订单状态闭合；若尚未分账，不产生虚假的分账冲正。                       |
| R02  | 已完成订单退 SKU1 的 1 件：提交申请→填写买家退货快递公司/单号→运营确认收到退货→审核退款 | 售后与物流信息可回看；确认收货前不能退款；审核后退款金额为该订单明细成交单价；退款成功才回补库存、冲正资金与分账。   |
| R03  | 同单再退剩余 1 件                                                                       | 两次退款累计不超过原实付；第 1 次保持部分退款状态，第 2 次转全退终态；各方冲正累计不超过各自原入账，余额与流水闭合。 |
| R04  | 退货单号为空、错误或重复；运营未确认收货就点通过；驳回申请                              | 必填和状态校验有效；未收货不触发退款；驳回后不产生退款及冲正，原因在买家和后台可见。                                 |
| R05  | 重复审核、重复退款请求、重复消息/重试、退款失败后重试                                   | 同一退款只退一次储值、只回补一次库存、只冲正一次各方账本；失败不记作成功，重试关联原售后与退款记录。                 |
| R06  | 同单包含不同供应商/成本/佣金 SKU，只退其中一种                                          | 核对被退明细的退款额及各方原始份额、实际冲正份额和剩余份额；特别记录比例冲正是否错误扣到未退 SKU 的供应商。          |

每笔退款同时核对：会员储值 `退款后余额 = 退款前余额 + 实际退款额`；`refund` 和 `mall_after_sale` 终态一致；`settlement_record.original_amount = 当前剩余 amount + 累计 refunded_amount`（正金额记录）；每方退款流水仅一次；全部参与方的原入账减累计冲正等于当前结算剩余。检查 `reconcile_issue` 是否出现余额不足或冲正失败，不能只看小程序“退款成功”。

## 5. 分账与团长专项

| 编号 | 场景                                                       | 预期                                                                                               |
| ---- | ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| D01  | A 购买有佣金 SKU1 并确认收货                               | 普通用户成交价包含佣金；佣金计入其归属团长主体；平台 + 供应商 + 团长 = 实付，其他三方为 0。        |
| D02  | B 购买同一 SKU 并确认收货                                  | 成交价与 A 相同；无团长分账，佣金归平台尾差；供应商份额不变。                                      |
| D03  | 团长 C 自购同一 SKU 并确认收货                             | 页面与成交价低于 A/B，差额为佣金 × 件数；订单佣金快照与团长分账均为 0；无“自己给自己提成”。        |
| D04  | A、C 购买佣金为 0 的 SKU2                                  | 展示和实付同价，团长分账为 0。                                                                     |
| D05  | 下单后修改商品售价、佣金、成本或归属团长，再完成订单及退款 | 原订单价格、供应商、团长和分账快照不变；退款按原单快照对账。                                       |
| D06  | D01/D03 完成后分别做部分退、全部退                         | 按退款单号核对平台、供应商、团长的退款冲正流水；自购单不得冲正不存在的团长佣金；重复事件不重复扣。 |

## 6. 执行顺序与通过标准

1. 先记录版本、测试数据和基线；运行小程序 `npm run check`，确认开发者工具可正常编译并连接目标 API。测试过程保存 Console 与 Network 错误。
2. 先执行 M01–M03 和 D01–D04 的价格、支付与分账主链；按订单号逐单核对，不混用账号或余额。
3. 对已收货订单执行 R02–R06；实际退货签收证据与系统“商家确认收货”一致后才发起退款。另执行 R01 发货前整单退款。
4. 对每笔单据保存页面、接口、后台、余额、库存、快照和流水证据，形成逐单对账表；资金/归属/库存错误列 P0，主流程阻断或未收货可退款列 P1。
5. 通过条件：全部主流程用例通过、买家资金净变化与支付减退款相符、各方分账及冲正守恒、无重复入账或退款、退货物流可追溯且未收货不能退款。任何阻断用例失败时不宣称“整体流程通过”，记录缺陷与重测结果。

当前文档是测试方案和静态代码核对结论，尚未在微信开发者工具执行本轮用例，也尚未产生新的真实支付或退款记录。
