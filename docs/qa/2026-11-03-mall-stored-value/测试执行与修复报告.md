## 发现并处理的问题

1. **余额不足原因被覆盖**：已建单后的储值业务错误显示可读原因，500 等内部异常保持安全通用提示，仍可到订单恢复支付。
2. **建单期间切换支付选项造成错通道**：冻结本次建单渠道，付款遵从服务端订单渠道。
3. **储值页余额陈旧与旧账号回包污染**：页面进入时刷新远端余额，合并同账号在途请求，保存前检查账号。
4. **补偿误退及并发窗口**：已发货/已退款且有成功支付单的意图转 DONE；每个补偿在独立事务内锁订单，与正常支付串行。
5. **余额不足后原单无法补付**：用 NO_DEBIT 区分“没有扣款”和“已经回冲”；仅原用户、原金额可按条件重开，真实 COMPENSATED 不重开。
6. **线上退款后订单详情 500**：发布已有 SQL 修复，直接对 JSON_TABLE 的 INT quantity 求和，避免再 JSON_EXTRACT。原 B 订单详情恢复正常。
7. **两次部分退款后订单仍已发货**：成功退款事务先写售后 SUCCESS，再计算累计数量；正常储值同步退款和微信异步退款均覆盖。已有成功退款可通过原退款号仅修订单投影，不重退资金、不回补库存、不重复发事件。
8. **恢复入口后缓存仍返回旧配置**：定位到 redis-cli AUTH 失败可能保持 DB0 却退出 0，导致错误声称清除了 DB2 缓存。脚本现仅在 Redis 明确无密码时重试无 AUTH；其他认证错误直接失败。精确失效后公开 API 与开发者工具都出现唯一商城入口。

修复均保留原工作区改动，针对新增失败回归实施；没有清理、回退、暂存或提交既有未提交内容。
