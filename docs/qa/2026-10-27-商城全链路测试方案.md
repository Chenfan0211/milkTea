# 商城全链路测试方案（2026-10-27）

> 适用范围：商城商品创建 → 上架 → 小程序浏览/加购 → 结算 → 下单 → 支付状态机 → 发货收货 → 分佣 → 整单退款与部分退货退款 → 运营后台。
> 本次口径：正式生产环境、低峰停机窗口、技术上线验收。**本次不上传体验版、不发布线上小程序、不发起真实微信支付与退款**，因此真实资金链路明确列为后续待办，不得据此宣称资金验收完成。

### 3.9 数据库对账

重点表与核对口径：

| 表                              | 核对内容                                                      |
| ------------------------------- | ------------------------------------------------------------- |
| `orders` / `order_item`         | 金额、状态、`order_type`、快照字段、`distribution_commission` |
| `app_user_address`              | 地址上限、默认唯一、下单快照                                  |
| `order_shipping`                | 快递公司/单号与状态一致                                       |
| `mall_sku`                      | `stock` / `locked_stock` 与库存流水闭合                       |
| `mall_stock_log`                | `biz_type + biz_no` 幂等，无重复入账                          |
| `refund`                        | `after_sale_id`、`original_amount`、退款状态                  |
| `mall_after_sale`               | 状态流转、退款数量不超过购买数量                              |
| `settlement_record`             | `original_amount` / `refunded_amount` 累计冲正                |
| `split_snapshot`                | 六方金额守恒、`leader_amount`                                 |
| `user_leader`                   | 一用户最多一个团长                                            |
| `subject_account` / `fund_flow` | 余额与流水一致，无重复记账                                    |
| `event_outbox`                  | 事件状态与消费结果                                            |
