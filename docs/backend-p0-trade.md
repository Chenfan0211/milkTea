## 二、订单状态机

```
CREATED --支付--> PAID --核销--> VERIFIED --(T+1)--> 台账 SETTLEABLE
   |                |                                        |
   |                +--退款(未结算)--> REFUNDED <-------------+
   +--(超时/取消)--> CANCELED                    已结算则禁止退款
```

## 三、分账规则（对齐方案 D-05/D-07）

- 分账基数 = 订单**实付金额**，时光币兑换与抵扣不参与分账；
- 比例 **万分比**，五方合计必须 = **10000**，否则抛错拒绝分账；
- 金额精确到分，**尾差归平台**（平台 = 实付 − 其余四方）；
- 分账在**核销（消费）时**触发，未消费不入账；
- 渠道无归因时，渠道部分归平台；
- 快照不可变（`total_check` 校验五方之和 = 实付）。

## 四、幂等与并发保护

| 场景 | 机制 | 验证结果 |
|------|------|---------|
| 重复支付 | 订单行锁 `for update` + 状态机 | `400 订单已支付，请勿重复支付` |
| 重复核销 | 订单行锁 + 状态机 | `400 订单已核销，请勿重复核销` |
| 重复退款 | 订单行锁 + 退款状态 | `400 订单已退款` |
| 重复分账 | 快照存在性检查 | 已有快照直接返回 |
| 资金穿透 | 已进入可结算/已结算禁止退款 | `400 订单已结算，不可退款` |

## 六、已知限制（后续批次处理）

1. **供应商分账未入账**：商品→供应商归属关系未建模，供应商份额暂归平台兜底。
2. **支付为 Mock**：`MockPaymentGateway` 未做真实验签，接入微信支付时需新增 `WxPayGateway` 实现。
3. **退款为整单退款**：不做部分退款（对齐方案 D-07）。
4. **定时结算任务**：`SettlementJob` 每日 01:00 执行，联调时可通过 `/finance/settle` 手动触发。
