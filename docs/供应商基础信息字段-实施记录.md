## 一、需求确认（动手前先澄清，避免白做）

原「供应商管理」页只能维护 **编码 / 名称 / 状态**；`supplier_profile` 表仅有
`product_count` + `status`，**没有任何联系信息**，运营无法记录对接人、电话等。

经确认，本次范围定为：

| 项 | 决定 |
|----|------|
| 字段范围 | **联系方式组**：联系人、联系电话、地址、邮箱、备注 |
| 必填约束 | **仅「联系电话」必填**，其余选填 |

> 排除了银行账号等结算类字段（涉及敏感信息，需另做权限控制）。

## 二、数据库改动（V37 迁移）

`server/src/main/resources/db/migration/V37__supplier_profile_contact_fields.sql`

| 列 | 类型 | 说明 |
|----|------|------|
| `contact_name` | VARCHAR(64) | 联系人 |
| `phone` | VARCHAR(32) | 联系电话（接口层必填）|
| `address` | VARCHAR(255) | 地址 |
| `email` | VARCHAR(128) | 邮箱 |
| `remark` | VARCHAR(255) | 备注 |

### 幂等设计（吸取 V31 教训）

每个 `ADD COLUMN` 都先用 `information_schema` 判断列是否存在，重复执行安全。
**刻意不手工写 Flyway 历史表** —— V31 曾因伪造 checksum 导致线上服务无法启动。

### 存量数据回填

`phone` 为必填，若不回填，存量 3 条供应商在编辑时会因必填校验无法保存。
故按主体 id 生成占位号码并标注「待补充」：

```
phone  = 000-0000-0401 / -0402 / -0403
remark = 存量数据：联系电话待补充
```

## 三、后端改动

`server/src/main/java/com/wuling/subject/controller/AdminSubjectProfileController.java`

| 位置 | 改动 |
|------|------|
| `toRow`（SUPPLIER 分支）| 返回新字段：contactName / phone / address / email / remark |
| `upsertSupplierProfile` | 写入新字段；`phone` 走 `required()` 校验必填 |

### 一个实现细节（容易踩坑）

原来写档案用的是 `Map.of(...)`，但 **`Map.of` 不允许 null 值** ——
地址/邮箱/备注都是选填，运营留空传进来就是 null，会直接抛 NullPointerException。
故改为 `LinkedHashMap`（允许 null，`upsertProfile` 用占位符写成 SQL NULL）。

## 七、过程中发现的问题（已处理）

1. **本机残留 dev 进程锁住构建产物**：`server/target/*.jar` 被一个 `--spring.profiles.active=dev`
   的 Java 进程占用（PID 34088，本机 8090 端口的遗留 dev 服务），导致 `mvn clean` 失败。
   已确认属遗留进程后停止该进程再构建。
2. **既有 CI 守卫拦截了新登记要求**：`DedicatedEndpointConsistencyTest` 报出 3 个详情页
   （snapshot-detail / role-detail / verify-detail）调用专用接口但未登记。
   这 3 个是**早前任务改动的文件**，已补充登记 `AdminDetailQueryController` 并纳入覆盖。
