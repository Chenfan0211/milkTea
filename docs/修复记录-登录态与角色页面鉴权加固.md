# 修复记录：小程序「已登录却提示未登录」排查与鉴权加固

> 日期：2026-10-10
> 范围：小程序端（user-h5）+ 后端 file-service
> 背景：排查「用户已登录、接口却提示未登录」问题，并顺带加固登录态与角色页面鉴权覆盖。

---

## 一、问题背景与根因

前端登录态分为三级（auth-state.js 统一判定）：

| 级别       | 含义                                        |
| ---------- | ------------------------------------------- |
| anonymous  | 无 token，未登录（只能浏览）                |
| authorized | 有 token 但未绑定手机号（可浏览，不可交易） |
| full       | 有 token 且已绑定手机号（可正常交易）       |

排查发现三类会导致「已登录却提示未登录」的隐患：

1. 后端返回码不一致：file-service 未登录返回 401，其余服务返回 8888（ResultCode.UNAUTHORIZED）。
   前端 request.js 只识别 8888/9999 做静默重登，401 被当成普通业务错误抛出，不自动重登。
2. 静默重登失败提示笼统：token 过期且重登失败时弹「需要登录」，与用户「明明刚登录」的体感矛盾。
3. 部分页面缺登录守卫：签到、若干查询页、以及 packageRole 角色页面未在入口做登录态校验，
   未登录时接口 401 被吞，页面误判为「暂无权限/空态」，而非友好引导登录。

---

## 二、改动清单

### 阶段 A：统一 file-service 返回码（后端）

文件：file-service/src/main/java/com/wuling/file/config/FileSecurityConfig.java

- 新增 import：com.wuling.common.api.ResultCode、jakarta.servlet.http.HttpServletResponse
- 未登录返回码由硬编码 401 改为 ResultCode.UNAUTHORIZED（8888），
  setStatus(401) 改为 setStatus(HttpServletResponse.SC_UNAUTHORIZED)，
  与 user-service / trade-service / auth-service 的 MiniAppAuthInterceptor 保持一致。

> 需执行 mvn -pl file-service -am compile 验证编译。

### 阶段 B：优化静默重登失败提示文案

文件：user-h5/utils/request.js

- 新增 describeAuthError(res)：区分 9999（登录过期）与 8888（令牌无效）给出准确文案。
- handleUnauthorized 弹窗文案由「需要登录」改为「登录已失效 / 是否重新登录」，
  并透传准确的失效原因到授权页。

### 阶段 C：补齐小程序页面登录守卫

| 文件                                       | 改动                                                    |
| ------------------------------------------ | ------------------------------------------------------- |
| pages/points-signin/points-signin.js       | 签到 handleSignIn 加 requireLogin，拆出 doSignIn        |
| pages/points-detail/points-detail.js       | 积分记录 onShow 加 requireLogin，拆出 loadPointsRecords |
| pages/exchange-records/exchange-records.js | 兑换记录 onShow 加 requireLogin                         |
| pages/coupon-list/coupon-list.js           | 我的优惠券 onShow 加 requireLogin                       |
| pages/gift-card-orders/gift-card-orders.js | 礼品卡订单 onShow 加 requireLogin                       |

### 阶段 D：角色页面登录守卫

文件：user-h5/utils/role-page.js（共享守卫，覆盖 17 个角色页面）

- ensureBusinessRole / ensureRolesLoaded 增加登录态前置校验：
  未登录时 openLoginSheet 引导登录并提前返回，避免 /roles/mine 401 被 .catch 吞掉后页面误判「暂无权限」。

文件：user-h5/packageRole/role-center/role-center.js（角色中心入口）

- onShow 增加登录守卫（此页直接调 syncRolesFromRemote，未走共享守卫）。

文件：user-h5/packageRole/role-income/role-income.js（收益明细）

- loadIncome 开头增加登录守卫（同上为直接调 syncRolesFromRemote 的特例）。
