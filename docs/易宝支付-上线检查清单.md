## 一、参数总表与现状

### 1.1 必填（缺失则易宝通道不可用）

判定位置：`server/src/main/java/com/wuling/system/controller/YeepayConfigInternalController.java:73`

```java
if (appKey == null || merchantNo == null || encPrivateKey == null) {
    return incomplete("易宝配置不完整（需要 appKey / merchantNo / privateKey）");
}
```

| 参数               | 存哪                          | 敏感         | 现状            | 从哪拿                   |
| ------------------ | ----------------------------- | ------------ | --------------- | ------------------------ |
| `yeepayAppKey`     | `platform_profile.pay_config` | 明文         | **已提供**      | 易宝开放平台 → 应用管理  |
| `yeepayMerchantNo` | 同上                          | 明文         | **已提供**      | 服务商主商编，签约时分配 |
| `yeepayPrivateKey` | 同上（`v1:` 前缀密文）        | **AES 加密** | **已提供(SM2)** | 开放平台 → 密钥管理下载  |

### 1.2 强烈建议（缺失只告警，但功能残缺）

| 参数                       | 缺失后果                                                                                                          | 现状     |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------- |
| `yeepayPlatformMerchantNo` | `YeepayOnboardService:225` 抛 `IllegalStateException`，子商户**无法入驻**；平台份额无法分账，订单卡在「部分分账」 | **缺失** |

代码依据：

```java
private String requireParentMerchantNo() {
    String platform = properties.getPlatformMerchantNo();
    if (platform == null || platform.isBlank()) {
        throw new IllegalStateException(
                "易宝平台商商编未配置：子商户入网必须以平台商为上级，否则无法接收分账");
    }
    return platform;
}
```

### 1.3 可选

| 参数                 | 说明                                  | 现状           |
| -------------------- | ------------------------------------- | -------------- |
| `yeepayYopPublicKey` | 验证易宝回调签名；留空由 SDK 远程拉取 | 缺失（可后补） |

### 1.4 私钥类型：支持 RSA2048 与 SM2（国密）

**易宝会按应用签约类型签发不同算法的私钥**，两类都要能对接：

| 类型        | 特征                                   | 依赖包                      | 签名算法      |
| ----------- | -------------------------------------- | --------------------------- | ------------- |
| RSA2048     | PKCS#8，OID `1.2.840.113549.1.1.1`     | `yop-java-sdk-crypto-inter` | SHA256withRSA |
| SM2（国密） | PKCS#8，曲线 OID `1.2.156.10197.1.301` | `yop-java-sdk-crypto-gm`    | SM3withSM2    |

**当前应用 `app_10094363805` 下发的是 SM2 国密私钥**（已实测解码确认）。

代码已支持自动识别，运营无需手动选类型：`YeepayPrivateKeySupport#detectCertType`
读 DER 里的 OID 判断，再交给对应解析器（SM2 → `YopSm2PrivateKeyParser`，
RSA → `RSAKeyUtils`）。

回归测试：`YeepayPrivateKeySupportTest`（类型识别 + 解析）、
`YeepaySignProcessorAvailableTest`（SPI 注册 + 真实签名）。

> 若未来易宝改发 RSA 私钥，无需改代码，直接粘贴即可。

### 1.5 环境变量（不进数据库）

| 变量                        | 作用                                | 缺失后果                                                                          | 现状     |
| --------------------------- | ----------------------------------- | --------------------------------------------------------------------------------- | -------- |
| `APP_SENSITIVE_KEY`         | AES-256-GCM 密钥，Base64 的 32 字节 | 保存私钥直接被拒：`敏感字段加密未配置（APP_SENSITIVE_KEY），拒绝明文存储商户私钥` | **缺失** |
| `YEEPAY_CHANNEL=yeepay`     | 总开关                              | 一个易宝 Bean 都不装配，不发起任何请求                                            | **缺失** |
| `YEEPAY_NOTIFY_BASE_URL`    | 回调基础地址                        | 默认 `https://api.wulingshiguang.top`，可不配                                     | 用默认值 |
| `YEEPAY_SANDBOX`            | 沙箱开关                            | 默认 `false`                                                                      | 用默认值 |
| `YEEPAY_DIVIDE_INTERVAL_MS` | 分账间隔                            | 默认 2500ms（易宝要求 2-3 秒）                                                    | 用默认值 |
| `YEEPAY_HTTP_TIMEOUT_MS`    | HTTP 超时                           | 默认 8000ms                                                                       | 用默认值 |

## 三、阻塞项：后台无录入入口

**问题**：后端接口已就绪，前端没有调用它的页面。

后端已有（`PlatformProfileController`）：

| 接口                                | 用途                                                     |
| ----------------------------------- | -------------------------------------------------------- |
| `GET /api/v1/admin/platform/yeepay` | 读配置（私钥不回显，只返回 `privateKeyConfigured` 布尔） |
| `PUT /api/v1/admin/platform/yeepay` | 存配置（私钥 AES 加密后落库，PEM 头尾自动清洗）          |

前端现状（`src/views/subject/platform/index.vue`）只有 4 个字段：

```js
{ key: 'appid',     label: '小程序AppID' },
{ key: 'appSecret', label: 'AppSecret', type: 'password' },
{ key: 'mchId',     label: '微信支付商户号' }
// 没有任何易宝字段
```

**影响**：即使配好 `APP_SENSITIVE_KEY` 并重启，也无法通过 UI 录入易宝参数。`docs/易宝对接-部署与配置说明.md:38` 描述的「在运营后台维护」目前**与实现不符**。

**解决方式（三选一）**：

1. 开发易宝配置 UI（推荐）—— 平台主体页加易宝 Tab
2. 临时用 `PUT /api/v1/admin/platform/yeepay` 直接调接口（需先有 `APP_SENSITIVE_KEY`）
3. 直接写 SQL —— **不推荐**，私钥需手工 AES 加密，易错

## 四、上线步骤（按依赖顺序）

### 第 0 步：生成敏感密钥（前置条件）

```bash
# Linux / macOS
openssl rand -base64 32

# Windows PowerShell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Max 256 }))
```

写入 `/opt/wuling/app/secrets.env`：

```
APP_SENSITIVE_KEY=<生成的值>
```

**必须保持稳定**：一旦变更，已加密的私钥全部无法解密，需重新录入。

### 第 1 步：录入易宝参数

需要 5 项（其中私钥敏感）：`appKey`、`merchantNo`、`platformMerchantNo`、`privateKey`、`yopPublicKey`（可选）。

前提：第 0 步已完成，否则保存私钥报「拒绝明文存储商户私钥」。

### 第 2 步：打开通道开关并重启

`secrets.env` 追加：

```
YEEPAY_CHANNEL=yeepay
```

重启 `trade-service`（配置在 `ApplicationReadyEvent` 拉取，**必须重启**）：

```bash
cd /opt/wuling/build
IMAGE_TAG=<当前 tag> docker compose -f docker-compose.prod.yml --project-name wuling up -d --no-deps trade-service
```

验证日志应出现：

```
易宝通道已启用，等待从数据库加载配置
易宝配置加载完成：appKey=已配置 服务商商编=已配置 平台商商编=已配置
易宝 YopClient 已创建 appKey=xxxxxxxx*** sandbox=false
```

若出现 `易宝配置不完整：...`，回到第 1 步补配。

### 第 3 步：易宝后台配置回调地址

必须在易宝开放平台登记（详见 `易宝对接-部署与配置说明.md:185`）：

```
https://api.wulingshiguang.top/api/v1/app/yeepay/notify/pay
https://api.wulingshiguang.top/api/v1/app/yeepay/notify/clearing
https://api.wulingshiguang.top/api/v1/app/yeepay/notify/refund
```

### 第 4 步：商户入驻

运营在「主体管理 → 入驻与签约」逐个提交。需要商户提供：法人姓名/证件号/证件照正反面、营业执照、联系人信息、经营地址。

入驻成功后 `subject_merchant_onboard.yeepay_merchant_no` 写入子商编——**这是分账的 `ledgerNo`**。

### 第 5 步：商户绑结算卡

「主体管理 → 结算卡」录入，`subject_payout_account.yeepay_settle_card_id` 写入卡 ID。提现需要它。

### 第 6 步：灰度验证

详见 `docs/易宝收款-联调清单.md`。最小验证路径：

1. 一笔小额微信小程序支付（走易宝通道）→ 支付成功
2. 支付回调到达 → `payment` 表状态正确
3. 核销 → 分账（注意 `DIVIDE_HOLD_DAYS` 默认 7 天冻结期）
4. 分账成功后 `settlement_record` 有 `yeepay_divide_detail_no`
5. 退款 → 归集（`divideBackDetail`）

## 六、风险提示

| 风险                      | 说明                                 | 规避                                            |
| ------------------------- | ------------------------------------ | ----------------------------------------------- |
| `APP_SENSITIVE_KEY` 丢失  | 私钥密文永久无法解密                 | 立即备份到密码管理器，且与数据库备份分开存      |
| `APP_SENSITIVE_KEY` 变更  | 同上                                 | 变更前先导出私钥明文，改后重新录入              |
| 误改 `PAY_CHANNEL`        | 会影响微信收款（现有主力通道）       | **只加 `YEEPAY_CHANNEL`，不要动 `PAY_CHANNEL`** |
| 未配 `platformMerchantNo` | 订单卡在「部分分账」，退款需人工介入 | 上线前务必确认已开通「平台商」子商户            |
| 入驻为 0 就开放           | 用户下单后分账失败                   | 先让至少 1 家门店完成入驻+绑卡再开门            |
