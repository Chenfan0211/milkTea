# 退款管理调整方案（已确认版）

> 确认口径：① 接真实微信退款（证书/回调地址先留空占位）；② 退款中订单保持 `PAID + refund_status=PENDING`，仅退款成功才变 REFUNDED；③ 失败单加「重新退款」按钮。

## 一、需求与状态机

| # | 需求 | 目标 |
|---|------|------|
| 1 | 列表显示商品信息 | 增加「商品信息」「门店」列 |
| 2 | 不做审核 | 删除/废弃本地假审核，首页 KPI 由「待审核退款」改「退款失败」 |
| 3 | 用户取消即退款 | 保持现有 `AppOrderController.cancel` 分流，固化口径 |
| 4 | 状态仅 3 种 | `REFUNDING`(退款中) / `FAILED`(退款失败) / `SUCCESS`(退款成功) |

状态机：
```
用户取消已支付订单
  -> 写 refund(REFUNDING) + 订单 refund_status=PENDING（事务提交）
  -> 调微信 v3 退款下单（SDK RefundService.create）
       ├ 受理成功 -> 保持 REFUNDING，等退款结果通知
       └ 同步失败 -> 置 FAILED（订单仍 PAID，可重试）
微信退款结果通知（验签+解密+幂等）
  ├ SUCCESS -> refund=SUCCESS + 订单 REFUNDED + 发台账冲正 MQ
  └ ABNORMAL/CLOSED -> refund=FAILED（订单仍 PAID）
```

## 二、后端改动（trade-service）

1. `PaymentGateway` 新增 `refund(...)` + `RefundApplyResult`。
2. `WechatPayGateway` 实现微信 v3 退款下单（SDK `refund.RefundService`）。
3. 新增 `WxRefundNotifyController`：验签解密（复用 NotificationParser）+ 幂等 + 状态流转。
4. `WxPayProperties` 增加 `refundNotifyUrl`（回调地址先留空）。
5. `WxPaySdkConfig` 增加 `RefundService` Bean（SDK）。
6. `RefundService.refund` 改造：先落 REFUNDING → 事务后调三方 → 失败置 FAILED；冲正 MQ 后移到「退款成功」。
7. 新增 `RefundService.markRefundSuccess / markRefundFailed / retry`。
8. `AdminTradeQueryController.refunds` 关联订单+商品，返回 summary/store，支持 status 过滤。
9. `server CrudRegistry` refund 资源 filterable 增加 status。
10. 新增迁移 `V42__refund_status_3state.sql` 收敛历史状态。
