# 调整方案：下单成功订阅消息

> 日期：2026-10-22
> 目标：用户点击「提交支付 / 立即支付」时申请订阅授权；订单进入 PAID（微信支付回调成功、储值余额扣款成功，含 mock 通道置为已支付）后，发送「下单成功」订阅消息
> 状态：✅ 代码已实施，✅ 自动化验证通过，✅ 生产已部署并实发成功（2026-10-22 15:28），✅ 备注固定文案已部署（15:34）

## 一、背景与目标

- 小程序当前没有订阅消息能力，用户在支付成功后收不到任何微信服务通知。
- 本期只做「下单成功」一个模板，不做退款、核销、储值到账等其他模板。
- 订阅消息是支付成功后的旁路动作：发送失败、配置缺失、微信接口异常都不得影响下单、支付、回调与订单状态。

## 二、触发链路

```
小程序：用户点击「提交支付 / 立即支付」
  → wx.requestSubscribeMessage(tmplIds: [模板 ID])
  → 无论 accept / reject / ban / filter / fail / 不支持，都继续下单与支付
  → createOrder → 微信支付 / 储值余额支付

trade-service：支付入账事务
  → markPaid（生成取餐码）
  → publishOrderPaid（既有 outbox 事件，不动）
  → orderService.toDTO(order, items)
  → orderSubscribeNotifier.enqueueForOrder(order, dto)
  → TransactionSynchronization#afterCommit
  → 独立有界线程池
  → UserQueryPort.findOpenid(userId)
  → OrderSubscribeMessageClient.send(...)
  → POST https://api.weixin.qq.com/cgi-bin/message/subscribe/send
```

覆盖入口：

- 确认页「提交支付」：微信支付与储值余额支付；
- 订单详情「立即支付」：待支付订单继续支付。

### 4.2 新增类

| 类                                                       | 职责                                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `WxMiniappSubscribeProperties`                           | 承载 `app.wx.*` 配置                                                                   |
| `MiniAppAccessTokenProvider`                             | Redis 缓存 access_token，TTL = `expires_in - 300s`；JVM 内串行刷新；支持 invalidate    |
| `OrderSubscribeMessageClient`                            | 组装 5 个模板字段、POST 发送、40001 刷新 token 后重试一次；所有异常内部消化            |
| `OrderSubscribeNotifier`                                 | 支付事务 afterCommit 注册、异步投递、openid 查询、配置缺失跳过；任何异常不抛回支付链路 |
| 原 `OrderSubscribeTaskSink` / `OrderSubscribeDispatcher` | 已废弃删除；当前通过 `event_outbox` + `wuling.subscribe.order.queue` 持久化消费        |

### 4.3 PaymentService 触发点

- `settlePaid(...)`：微信支付回调 / mock 支付成功统一入账后调用；
- `payWithStoredValue(...)`：储值余额扣款成功后调用；
- 重复微信回调、重复支付请求由既有幂等逻辑拦截，不会重复注册发送。

### 4.4 失败语义

| 微信返回                       | 处理                                                              |
| ------------------------------ | ----------------------------------------------------------------- |
| `errcode=0`                    | INFO：发送成功                                                    |
| `40001`                        | WARN：清 token 缓存，重取后重试一次                               |
| `43101`                        | INFO：用户未订阅或额度已用尽，跳过                                |
| `47003` 等其他错误             | WARN：记录 errcode / errmsg；异常消息已脱敏 access_token / secret |
| 网络异常、线程池拒绝、配置缺失 | 记录日志后跳过；支付结果不受影响                                  |

## 七、已知边界

- 本期不做发送记录表、后台补发、发送结果查询；
- 订阅消息为一次性订阅，用户每次点击支付时重新授权；拒绝或额度已用尽时按 best-effort 跳过；
- 当前 `PAY_CHANNEL=mock` 也会触发发送，如需关闭设置 `WX_ORDER_SUBSCRIBE_ENABLED=false`；
- trade-service 当前按单实例部署，Redis 缓存 access_token 足够；多实例扩容时需补充跨实例刷新锁；
- 用户填写的订单备注仍会随订单入库、门店可见，但订阅消息的「备注」字段固定为「您已下单成功，餐点准备中！」，不再透传用户备注；
- 「储值支付失败后停留在待支付状态、订单详情无法继续走储值余额支付」是既有问题，不在本期修复；
- 不做退款、核销、储值到账等其他模板。

## 原生授权 + 持久队列改造（2026-10-22 最终版）

- 小程序只在“提交支付 / 立即支付”点击回调中调用一次原生 `wx.requestSubscribeMessage`，不再使用自定义订阅选择页。
- trade-service 不再在线程池内直发微信，而是在支付事务内写 `subscribe_message_log` 和 `event_outbox`，事件路由到 `wuling.subscribe.order.queue`。
- `OrderSubscribeConsumer` 使用 `consumeAfterSuccess` 模式消费，发送成功或微信返回 `43101` 后 ACK；网络/限流等可重试错误走现有延迟重试和 `wuling.subscribe.order.queue.dlq`。
- DLQ 已纳入 `DlqMonitor.MONITORED`；回滚时停止消费者，保留队列和 outbox，不执行清空操作。
