## 快速定位（按你想解决的问题）

- **接口响应慢、数据库压力大** → 先看 `02`（N+1），再看 `01`（缓存）
- **偶发 429 或被刷** → 看 `03`
- **多个服务共享 Redis 出现 key 混乱/互相覆盖** → 看 `04`
- **上传大文件导致堆内存飙高 / 被传恶意文件** → 看 `05`

## 通用原则（贯穿所有实践）

1. **fail-open 优先**：缓存、限流这类「加速/防护」组件不可用时，不能拖垮主链路——缓存未命中回源 DB、限流 Redis 挂掉放行。
2. **fail-closed 用安全**：病毒扫描这类「安全」组件不可用时，宁可拒绝也不放行。
3. **维度越细越精准**：限流 key、缓存 key 都要带上能区分业务的维度，避免误伤。
4. **TTL 兜底**：缓存、限流窗口都设过期时间，防止脏数据永久残留。
5. **可观测**：关键判定点（429、缓存失效、扫描失败）必须打日志，能定位到 db/key 一级。
