# 文件上传安全与内存优化实践

> 场景：文件/图片上传服务，需同时解决三个问题：
> ① 大文件整体读入堆内存导致内存飙高；② 上传恶意文件（伪造扩展名、病毒）；③ 文件名冲突覆盖。
> 核心思路：**流式处理 + 安全校验前置 + 防覆盖落盘**，安全校验 fail-closed。

## 一、核心思路

```
上传流进来
  ├─ 流式读文件头（只读前 16 字节判类型），不加载全量内容
  ├─ 校验：扩展名 + 魔数（文件头）+ 声明 Content-Type 比对（仅告警）
  ├─ 病毒扫描（若启用）→ fail-closed：发现病毒或扫描失败都拒绝
  ├─ 尺寸校验（读 header 判宽高/像素，合法才全量解码）
  ├─ 重编码（剥离恶意元数据、统一格式）
  └─ 落盘：UUID 命名 + CREATE_NEW 防覆盖 + 路径越界防护
```

关键点：

1. **流式读文件头**——签名/类型判断阶段只读前 N 字节，不把整个文件读进堆内存。
2. **安全校验 fail-closed**——病毒扫描失败也拒绝（「宁可错杀」），与缓存/限流的 fail-open 相反。
3. **落盘防覆盖**——UUID + `CREATE_NEW`，冲突则重新生成，绝不覆盖既有文件。
4. **路径越界防护**——`normalize()` 后校验父目录等于存储根，防路径穿越。

## 二、可复制的代码骨架

### 流式入口（读文件头判类型）

```java
public StoredImage store(String originalFilename, InputStream in, String declaredType) {
    if (in == null) throw new InvalidFileException("文件内容为空");
    try {
        // 只读文件头判类型，不加载全量
        byte[] head;
        try {
            head = in.readNBytes(16);
        } catch (IOException e) {
            throw new InvalidFileException("文件读取失败");
        }
        if (head.length == 0) throw new InvalidFileException("文件内容为空");

        FileType type = FileTypeValidator.validate(originalFilename, head);

        // 声明 Content-Type 与真实类型不符：仅告警（客户端头不可信，不作为拒绝依据）
        if (declaredType != null && !declaredType.isBlank()
                && !declaredType.equalsIgnoreCase(type.mimeType())) {
            log.warn("declared content-type mismatch: declared={} actual={}",
                    declaredType, type.mimeType());
        }

        // 已读的 head 与剩余流拼接，保证解码器拿到完整文件头
        InputStream complete = new SequenceInputStream(
                new ByteArrayInputStream(head), in);

        BufferedImage decoded = decodeWithDimensionLimits(complete);
        byte[] encoded = reencode(decoded, type);
        return writeEncoded(originalFilename, encoded, type);
    } catch (InvalidFileException e) {
        throw e;
    } catch (Exception e) {
        throw new InvalidFileException("文件读取失败");
    }
}
```

### 病毒扫描（fail-closed，可选注入）

```java
/** 可选注入扫描器：未启用时保持 null */
@Autowired(required = false)
public void setScanner(VirusScanner scanner) {
    this.scanner = scanner;
}

private void scanIfEnabled(byte[] content) {
    if (scanner == null) return;
    try {
        if (!scanner.isClean(new ByteArrayInputStream(content))) {
            throw new InvalidFileException("检测到病毒或恶意内容，已拒绝上传");
        }
    } catch (VirusScanner.ScanException e) {
        // fail-closed：扫描服务不可用同样拒绝，保留明确语义
        throw new InvalidFileException("病毒扫描服务不可用，已拒绝上传");
    }
}
```

### 落盘防覆盖 + 路径越界防护

```java
private StoredImage writeEncoded(String originalFilename, byte[] encoded, FileType type) {
    while (true) {
        String storedName = UUID.randomUUID().toString().replace("-", "") + "." + suffix;
        Path target = storageRoot.resolve(storedName).normalize();
        // 路径越界防护：normalize 后父目录必须等于存储根
        if (!target.getParent().equals(storageRoot)) {
            throw new IllegalStateException("生成的文件路径越界");
        }
        try {
            Files.write(target, encoded, StandardOpenOption.CREATE_NEW, StandardOpenOption.WRITE);
            return new StoredImage(publicBaseUrl + "/" + storedName, storedName, type.mimeType(), encoded.length);
        } catch (FileAlreadyExistsException ignored) {
            // UUID 冲突概率极低；若发生则重新生成，绝不覆盖既有文件
        } catch (IOException e) {
            throw new IllegalStateException("文件落盘失败: " + storedName, e);
        }
    }
}
```

### 流式解码（先读 header 判尺寸，合法才全量解码）

```java
private BufferedImage decodeWithDimensionLimits(InputStream in) {
    try (ImageInputStream input = ImageIO.createImageInputStream(in)) {
        if (input == null) throw new InvalidFileException("图片内容无法读取");
        Iterator<ImageReader> readers = ImageIO.getImageReaders(input);
        if (!readers.hasNext()) throw new InvalidFileException("无法识别的图片格式");
        ImageReader reader = readers.next();
        try {
            reader.setInput(input, true, true);
            int width = reader.getWidth(0);
            int height = reader.getHeight(0);
            // 尺寸校验：宽高、像素总数超限即拒绝（解压炸弹防护）
            if (width > maxDimension || height > maxDimension) {
                throw new InvalidFileException("图片尺寸超限");
            }
            if ((long) width * height > maxPixels) {
                throw new InvalidFileException("图片像素总数超限");
            }
            return reader.read(0); // 尺寸合法后才全量解码
        } finally {
            reader.dispose();
        }
    } catch (IOException e) {
        throw new InvalidFileException("图片读取失败");
    }
}
```

## 三、关键决策与权衡

| 决策点   | 选择                                    | 理由                                        |
| -------- | --------------------------------------- | ------------------------------------------- |
| 类型判断 | 读文件头魔数，不信任扩展名/Content-Type | 扩展名和客户端头都可伪造                    |
| 内存     | 流式读头 + 尺寸合法才全量解码           | 避免大文件整体进堆                          |
| 病毒扫描 | fail-closed（失败也拒绝）               | 安全组件「宁可错杀」，与缓存 fail-open 相反 |
| 落盘     | UUID + CREATE_NEW                       | 防覆盖，冲突重试                            |
| 路径     | normalize + 父目录校验                  | 防路径穿越                                  |
| 解压炸弹 | 像素总数上限校验                        | 防超宽高比图片撑爆内存                      |

## 四、关键原则对比（易混淆）

| 组件类型            | 故障策略        | 例子                       |
| ------------------- | --------------- | -------------------------- |
| 加速/防护（非核心） | **fail-open**   | 缓存挂了回源、限流挂了放行 |
| 安全（核心）        | **fail-closed** | 病毒扫描挂了拒绝上传       |

> 记忆口诀：**「加速可降级，安全不放松」**。

## 五、验证方法

- 上传超大文件，观察堆内存不随文件大小线性飙升（流式处理生效）。
- 上传改扩展名的恶意文件（如 `.jpg` 实际是 `.exe`），应被魔数校验拒绝。
- 上传病毒样本（启用扫描时），应被拒；停掉扫描服务再传，也应被拒（fail-closed）。
- 模拟路径穿越（文件名含 `../`），应被越界校验拦截。
