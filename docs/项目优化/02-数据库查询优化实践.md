# 数据库查询优化实践（N+1 → 批量预加载）

> 场景：列表接口需要返回每条记录的关联字段（分类名、规格数、门店名等），
> 朴素写法会「查一次主表 + 对每条记录再查一次关联表」，产生 N+1 查询。
> 核心思路：主表查一次，关联字段**按 id 集合批量查一次**，再用 Map 在内存组装。

## 一、核心思路

```
朴素写法（N+1 灾难）：
  查主表（1 次）
  遍历每条记录：
    查分类（1 次）  ← 每条都查
    查规格（1 次）  ← 每条都查
    查门店（1 次）  ← 每条都查
  → 1 + 3N 次查询

批量预加载（优化后）：
  查主表（1 次）
  查分类：WHERE id IN (...主表分类id集合)（1 次）
  查规格：WHERE 外键 IN (...主表id集合)（1 次）
  查门店名：WHERE 外键 IN (...) + 批量查主体名（1~2 次）
  内存 Map 组装
  → 4~5 次查询，与记录数 N 无关
```

关键点：
1. **先收集 id 集合**，再 `IN` 批量查询。
2. **用 `Map<外键, 关联数据>` 缓存查询结果**，组装时 O(1) 取。
3. **空集合短路**：`if (ids.isEmpty()) return Map.of()`，避免 `IN ()` 语法错误。

## 二、可复制的代码骨架

### 批量预加载三个映射

```java
// 1. 主表分页查询（已有逻辑）
Page<Item> page = itemMapper.selectPage(new Page<>(current, size), wrapper);
List<Item> records = page.getRecords();

// 2. 批量预加载三个关联映射（各查一次）
Map<Long, Category> categoryMap = loadCategoryMap(records);
Map<Long, List<Spec>> specMap = loadSpecMap(records);
Map<Long, List<String>> ownerNameMap = loadOwnerNameMap(records);

// 3. 内存组装（不再逐个查）
List<ItemDTO> dtos = records.stream()
        .map(r -> toDtoBatch(r, categoryMap, specMap, ownerNameMap))
        .toList();
```

### 批量加载方法

```java
/** 批量加载分类映射（外键 -> 分类） */
private Map<Long, Category> loadCategoryMap(List<Item> records) {
    List<Long> ids = records.stream()
            .map(Item::getCategoryId)
            .filter(Objects::nonNull)
            .distinct()
            .toList();
    if (ids.isEmpty()) return Map.of(); // 空集合短路，避免 IN ()
    return categoryMapper.selectList(
                new LambdaQueryWrapper<Category>().in(Category::getId, ids))
            .stream()
            .collect(Collectors.toMap(Category::getId, c -> c));
}

/** 批量加载规格映射（外键 -> 规格列表），用 groupingBy 分组成 Map */
private Map<Long, List<Spec>> loadSpecMap(List<Item> records) {
    List<Long> ids = records.stream().map(Item::getId).toList();
    if (ids.isEmpty()) return Map.of();
    return specMapper.selectList(
                new LambdaQueryWrapper<Spec>().in(Spec::getItemId, ids))
            .stream()
            .collect(Collectors.groupingBy(Spec::getItemId));
}

/** 批量加载归属名映射（外键 -> 名称列表），名称经远程端口批量查 */
private Map<Long, List<String>> loadOwnerNameMap(List<Item> records) {
    List<Long> ids = records.stream().map(Item::getId).toList();
    if (ids.isEmpty()) return Map.of();
    List<ItemOwner> links = ownerMapper.selectList(
            new LambdaQueryWrapper<ItemOwner>().in(ItemOwner::getItemId, ids));
    if (links.isEmpty()) return Map.of();
    // 批量查主体名（一次远程调用代替 N 次）
    List<Long> ownerIds = links.stream().map(ItemOwner::getOwnerId).distinct().toList();
    Map<Long, String> ownerNames = ownerPort.findNames(ownerIds);
    Map<Long, List<String>> result = new HashMap<>();
    for (ItemOwner link : links) {
        String name = ownerNames.get(link.getOwnerId());
        if (name != null) {
            result.computeIfAbsent(link.getItemId(), k -> new ArrayList<>()).add(name);
        }
    }
    return result;
}
```

### 批量组装 DTO

```java
/** 用预加载映射组装，不查库 */
private ItemDTO toDtoBatch(Item item,
                           Map<Long, Category> categoryMap,
                           Map<Long, List<Spec>> specMap,
                           Map<Long, List<String>> ownerNameMap) {
    ItemDTO dto = toDtoBase(item); // 基础字段（不含关联）

    Category category = item.getCategoryId() == null
            ? null : categoryMap.get(item.getCategoryId());
    dto.setCategoryName(category == null ? "-" : category.getName());

    List<Spec> specs = specMap.getOrDefault(item.getId(), List.of());
    dto.setSpecCount((int) specs.stream().map(Spec::getGroupCode).distinct().count());

    List<String> names = ownerNameMap.getOrDefault(item.getId(), List.of());
    dto.setOwners(names);
    return dto;
}
```

### 保留单个查询版本（写操作后回填用）

```java
/** 单个 DTO 组装：写操作后回填，低频，逐个查即可 */
private ItemDTO toDtoSingle(Item item) {
    ItemDTO dto = toDtoBase(item);
    // 这里逐个 selectById / selectList，频率低无性能问题
    ...
    return dto;
}
```

> 关键：**基础字段组装 `toDtoBase` 抽出来共用**，批量与单个都复用，避免两套字段赋值逻辑漂移。

## 三、关键决策与权衡

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 批量查询边界 | 按 id 集合 `IN` | 一次查回所有关联数据 |
| 组装方式 | Map + getOrDefault | O(1) 取，空值给默认 |
| 空集合 | `if empty return Map.of()` | 避免 `IN ()` SQL 语法错误 |
| 远程名称查询 | 端口批量 `findNames(ids)` | 把 N 次远程调用降为 1 次 |
| 单个回填场景 | 保留逐个查版本 | 写操作低频，不值得为 1 条做批量 |

## 四、效果对比

- 朴素写法：`1 + 3N` 次查询（N 为分页大小，如 20 条 → 61 次）
- 批量预加载：`4~5` 次查询，与 N 无关

> 分页越大、关联字段越多，收益越明显。

## 五、验证方法

- 打开 SQL 日志（MyBatis `log-impl: StdOutImpl`），观察列表接口 SQL 条数：应为「主表 + 每个关联各 1 条」，而非「每行一串」。
- 压测对比：同样分页大小下，批量预加载的 DB 往返次数不随分页大小线性增长。
