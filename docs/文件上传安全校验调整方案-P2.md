## 一、目标

在 file-service 的图片重编码【之前】，把原始字节流送交 ClamAV（clamd）做病毒扫描，
拦截携带恶意载荷的文件。这是应对「带病毒 JS / 图片内嵌恶意代码」的根本手段。

## 三、关键设计决策

1. **通信方式**：纯 JDK Socket 直连 clamd 3310 端口 INSTREAM 协议，不引入第三方 HTTP 客户端。
2. **部署形态**：clamd 加入中间件 compose（容器名 `wuling-clamav`），与 MySQL/Redis/Nacos 同层。
3. **失败策略**：fail-closed —— clamd 不可用（连接失败/超时/异常响应）时【拒绝上传】，绝不静默放行。
4. **向后兼容**：`app.clamav.enabled=false`（默认）时跳过扫描，本地开发/测试无需部署 clamd。

## 四、部署步骤（服务器）

> 可直接复制的完整片段文件：`deploy/clamav-compose-snippet.yml`（含注释与 volumes 说明）

1. 生产中间件 compose（`/opt/wuling/deploy/docker-compose.yml`）新增 clamav 服务（片段见 `deploy/clamav-compose-snippet.yml`）：
   ```yaml
   clamav:
     image: clamav/clamav:stable
     container_name: wuling-clamav
     restart: unless-stopped
     ports: ["3310:3310"]
     volumes: [clamav-data:/var/lib/clamav]
     healthcheck:
       test: ["CMD", "clamdscan", "--ping"]
       interval: 30s
       timeout: 10s
       retries: 5
       start_period: 120s
   ```
   并确保 clamav 容器接入 `wuling-net` 网络。
2. 重新构建并部署 file-service（`CLAMAV_ENABLED=true` 已由 prod compose 注入）。
3. 验证：上传正常图片成功；上传含 EICAR 测试签名的文件被拒。
