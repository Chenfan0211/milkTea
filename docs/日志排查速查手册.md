# 日志排查速查手册

> 适用范围：五零时光后端 8 个 Java 服务（生产 Docker 部署）
> 维护时间：2026-10-10

## 一、日志都存在哪里

所有日志最终汇聚到宿主机一个目录：**`/opt/wuling/logs/`**，按「服务名」区分文件。

| 层                      | 位置                                         | 内容                     | 保留                  |
| ----------------------- | -------------------------------------------- | ------------------------ | --------------------- |
| 当天活跃日志（主）      | `/opt/wuling/logs/{服务名}.log`              | 业务日志 + 接口调用日志  | 当天                  |
| 归档日志                | `/opt/wuling/logs/{服务名}.yyyy-MM-dd.N.log` | 历史（按天+大小拆分）    | 60 天                 |
| stdout（`docker logs`） | Docker `json-file` 驱动                      | 与文件内容相同的镜像副本 | 约 100MB 滚动，会丢弃 |

8 个服务对应 8 组文件（服务名前缀区分）：

```
gateway.log              gateway.2026-10-09.0.log   ...
auth-service.log         auth-service.2026-10-09.0.log ...
file-service.log         ...
marketing-service.log    ...
trade-service.log        ...
user-service.log         ...
product-service.log      ...
server.log               ...
```

目录内还有几个**非轮转、不参与清理**的文件：

- `alerts.log` —— 业务告警日志（资金对账异常等）
- `ALERT_PENDING` —— 未处理告警标记文件
- `health.log` —— 健康检查记录

## 二、日志怎么滚动与保留

- **滚动策略**：`SizeAndTimeBasedRollingPolicy`（按「天 + 大小」双重滚动）
  - 单文件超过 `maxFileSize=100MB` 拆分出序号文件（`N` 递增）
  - `maxHistory=60` 天，到期自动删除
  - `totalSizeCap=5GB` 总容量上限，超限删最旧归档
- **清理脚本**：`/opt/wuling/scripts/clean-logs.sh`（保留 60 天，cron 每天 03:10 执行）
- **体检脚本**：`/opt/wuling/scripts/check-logs.sh`（检查各服务是否正常写日志，异常 exit 1）

## 三、每条日志长什么样

统一格式（logback pattern）：

```
时间 [traceId] [线程] 级别 类名 - 消息
2026-10-10 14:32:05.123 [a1b2c3d4e5f67890] [http-nio-8081-exec-3] INFO  c.w.a.c.UserController - 登录成功
```

`[a1b2c3d4e5f67890]` 就是 **traceId**，同一次请求跨服务串起来排查的关键。

## 四、每次调用记录了哪些信息

分两层记录，职责不同：

### 网关层 `GatewayLogFilter`

```
trace={traceId} GW user={userId} {METHOD} {path}?{query} status={code} cost={ms}ms
```

- 记录：方法、路径、查询串（脱敏）、用户、状态码、耗时、traceId
- **不记录请求体（body）**——网关故意不缓存 body，避免拖慢吞吐

### 下游服务层 `RequestLogFilter`（各业务服务）

```
trace={traceId} user={userId} {METHOD} {path}?{query} status={code} cost={ms}ms req={body} [resp={body}]
```

- 记录：traceId、用户、方法、路径、查询串、状态、耗时、**请求体 req**、错误响应体 resp
- `req=` 是**入参 body**（能拿到具体参数）
- `resp=` 仅在 `status >= 400`（出错）时才记录，正常请求不记

## 五、能拿到具体参数吗

**能，但默认脱敏。** 敏感字段会被替换为 `***`：

| 敏感字段                                                                   | 处理                           |
| -------------------------------------------------------------------------- | ------------------------------ |
| token / accessToken / authorization / password / secret / sign / signature | 变成 `***`                     |
| encryptedData / iv / sessionKey / smsCode / code                           | 变成 `***`                     |
| 手机号                                                                     | `138****8000`（保留前 3 后 4） |

其他限制：

- body 超过 `app.log.request.max-body`（默认 2000 字符）截断
- 响应体只在出错时记录

### 想拿完整明文参数（临时排查）

设置环境变量 `LOG_REQUEST_FULL=true`（对应 `app.log.request.full=true`），**并重启服务**，即可原样输出全部参数（含 token/手机号等）。

⚠️ 风险：明文凭据落盘，**排查完必须关闭并重启**。

## 六、怎么按 traceId 排查一条完整调用链

1. 在网关日志里找到目标请求的 `trace=` 值（例如 `trace=a1b2c3d4e5f67890`）
2. 用该 traceId 在**所有服务**的日志里 grep：

```bash
cd /opt/wuling/logs
grep -rn "a1b2c3d4e5f67890" *.log *.20*.log
```

3. 能串出：网关入口 → 各下游服务 → 服务间内部调用的完整链路与每个环节的参数、状态、耗时。

> traceId 由网关生成，经 `X-Trace-Id` 请求头透传，下游 `RequestLogFilter` 复用；服务间 RestClient 内部调用也透传该头，因此跨服务可串联。

## 七、常用排查命令

```bash
cd /opt/wuling/logs

# 实时看某个服务的日志
tail -f gateway.log

# 看某个服务今天的日志
cat user-service.log

# 按关键词搜（如用户ID、订单号）
grep -n "13800000000" user-service.log trade-service.log

# 按 traceId 跨服务搜
grep -rn "a1b2c3d4e5f67890" *.log

# 看 docker 层（stdout，与文件内容一致，会滚动）
docker logs --tail 200 wuling-gateway
docker logs --since 30m wuling-user-service

# 日志体检
/opt/wuling/scripts/check-logs.sh

# 手动清理归档（默认 60 天）
/opt/wuling/scripts/clean-logs.sh
```

## 八、常见问题

| 现象                               | 排查方向                                                                    |
| ---------------------------------- | --------------------------------------------------------------------------- |
| 某服务当天日志不存在或长时间不更新 | 跑 `check-logs.sh`；检查 logback 写文件权限（宿主机目录属主应为 1000:1000） |
| 参数看不到（全是 `***`）           | 默认脱敏，临时开 `LOG_REQUEST_FULL=true` 并重启                             |
| 网关日志没有 body                  | 网关设计上不缓存 body，body 看下游各服务的 `req=`                           |
| 跨服务对不上 traceId               | 确认各服务已重新构建镜像并重启（旧版无 traceId 透传）                       |
| 归档日志被删太快                   | 检查 `LOG_MAX_HISTORY` / `LOG_RETENTION_DAYS` 是否被覆盖                    |
