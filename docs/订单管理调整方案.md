# 订单管理调整方案（已确认版）

> 确认口径：① 取消订单仅 `PAID`；② 前后端一起做；③ 保留详情路由，只把入口改为弹层，不跳新页面。

## 一、需求与改动清单

| # | 需求 | 目标口径 | 涉及层 |
|---|------|---------|--------|
| 1 | 只有已支付待核销订单可取消 | `status === 'PAID'` | 前端 +
  store 白名单 |
| 2 | 后台所有「详情」改弹层 | 不跳新页面，弹层展示 | 前端共享组件 |
| 3 | 门店改为搜索下拉框 | 可搜索 + 后端按门店过滤 | 前端 + 后端 |
| 4 | 核销码仅已支付展示 | 非 `PAID` 一律不展示 | 前端 + 后端 |

## 二、后端改动（trade-service）

1. `AdminOrderController.orders` 增加 `@RequestParam(required=false) Long storeSubjectId`。
2. `OrderService.pageOrders(current, size, status, search, storeSubjectId)` 增加门店过滤。
3. `OrderService.toDTO` 的 `pickupCode` 仅在 `PAID` 时下发，其余置空。

## 三、前端改动

1. `src/views/_shared/detail-types.ts`（新增）：抽出 `DetailField` / `DetailGroup`。
2. `src/views/_shared/DetailModal.vue`（新增）：通用详情弹层。
3. `src/views/_shared/types.ts`：`RowAction` 增加 `detail` 配置。
4. `src/views/_shared/AdminListPage.vue`：支持 `detail` 动作，弹层挂载；搜索下拉 options 响应式。
5. 订单/核销/快照/角色 4 个列表页：详情按钮改 `detail`，删除 `useRouter` 跳转。
6. `src/store/modules/admin/index.ts`：`refundOrder` 改为白名单（仅 PAID）。

## 四、验证

- `pnpm typecheck` / `pnpm build` 通过。
- 列表：待支付无取消按钮；非已支付核销码显示 `—`。
- 门店下拉可搜索、可清空、过滤生效（联调后端）。
- 4 处详情点击后停留当前页并弹层，URL 不变。
- `trade-service` 编译通过（`mvn -q -DskipTests compile`）。
