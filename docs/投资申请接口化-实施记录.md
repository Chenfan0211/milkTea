# 投资申请接口化改造（假数据清理收尾）

> 日期：2026-09-25
> 目标：把小程序端最后一块假数据 —— 投资人点位投资申请 —— 改为调用后端接口
> 状态：✅ 代码完成、后端已部署、测试全绿

---

## 一、背景

此前排查确认：小程序端唯一仍在用假数据的模块是「投资人点位投资申请」
（`utils/invest.js`）。它用 localStorage（`milkTea:invest-applications`）伪造整个申请流程，
`INVESTOR_ID = 'INV-1001'` 写死，申请不落库、运营后台看不到、换设备即丢。

用户确认的三项决策：

| 决策 | 内容 |
|------|------|
| 1 | 申请复用 `role_application` 链路 |
| 2 | 旧 localStorage 数据直接丢弃 |
| 3 | 投资人主体 id 从 `/roles/mine` 的 `boundSubjectId` 取 |

---

## 二、后端改动

`server/.../subject/controller/AppRoleController.java` 的 `apply` 接口：

- 新增支持 `subjectId`（目标门店）落库到 `role_application.subject_id`；
- 判重规则升级：指定了 subjectId 的申请按 `(role_type, subject_id)` 判重，
  未指定的普通角色申请仍按 `role_type` 判重；
- 新增 `asLong` 辅助方法。

### 审核联动（用户二次确认后补充）

用户确认：投资人投资门店审核通过后，**自动建立「门店↔投资人主体」绑定**，
`subject_id` 存目标门店，投资人主体从申请人当前角色取。

`SubjectBindingController.reviewApplication` 增加 INVESTOR 分支：

- 申请记录的 `subject_id` = 目标门店 id；
- 从 `user_role_grant`（role_code=investor）或 `app_user.bound_subject_id` 取申请人的投资人主体 id；
- 写 `store_profile.investor_subject_id = 投资人主体 id`；
- **不回写** `app_user.bound_subject_id`（用户已是投资人，绑定的是投资人主体而非门店）。

复用现有链路：`AppRoleController.apply`（提交）/ `myApplications`（查记录）/ 
`SubjectBindingController.reviewApplication`（运营审核）。**未新建表或接口**。

## 三、前端改动

### `utils/invest.js`（彻底重写）

- 删除 localStorage 读写（`INVEST_STORAGE_KEY`）、写死的 `INVESTOR_ID`；
- `submitApplication` → `api.applyBusinessRole('investor', { subjectId, name, phone, budget, remark, ... })`，返回 Promise；
- `listApplications` / `getApplicationDetail` → `api.fetchRoleApplications()` 过滤 `role_type=investor`；
- 新增 `refreshInvestCatalog` / `refreshInvestApplications` 拉取镜像；
- 新增 `setInvestCatalogForTest` / `setInvestApplicationsForTest`（对齐 store.js 的测试注入模式）；
- `getSpots` / `getInvestStats` / `getSpotById` 增加 `investorSubjectId` 参数，用于区分「我签的」（signed）与「别人签的」（occupied）。

### 4 个页面

| 页面 | 改动 |
|------|------|
| `role-invest` | `syncRole` 改为先拉 catalog + applications 再渲染；`getSpots(getCurrentSubjectId())` |
| `role-invest-apply` | `onLoad` 先拉 catalog；`submit` 改为 Promise.then |
| `role-invest-records` | `syncRole` 先拉 applications |
| `role-invest-detail` | `onLoad` 先拉 applications；`getApplicationDetail(recordId)` 单参数 |

## 四、测试更新

`user-h5/scripts/role-function-pages.test.mjs` 投资模块段重写：

- 旧测试断言「localStorage 同步状态机」（提交→pending→统计+1）已不适用；
- 新测试断言接口化语义：未同步前为空、注入 seed 后点位状态/统计/详情/时间线正确、
  提交前置校验拒绝不可申请点位、源码断言 `applyBusinessRole('investor')` + `subjectId`、
  断言不再写 localStorage。

顺带发现并修正两处归一化 bug：

| 问题 | 修正 |
|------|------|
| `businessStatus`（open）被误当 status → 全部点位判 disabled | 优先用 `s.status`（enabled/disabled）|
| `isSignedByMe` 把「任何绑定」都判 signed | 改为 `store.investorSubjectId === 当前投资人 subjectId` |
