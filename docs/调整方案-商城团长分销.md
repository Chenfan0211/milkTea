# 商城团长分销调整实施记录

> 实施日期：2026-10-27
> 范围：新增团长（LEADER）经营角色、用户-团长归属、商城 SKU 分销佣金、团长价格口径与分账归属。

## 一、调整目标

- **店主不参与商城分佣**：商城订单不再发放门店每件提成（storeRatio），原有点单订单分佣保持不变。
- **新增团长角色**：团长也是一个用户，可与其他经营角色（门店/资源方/投资人等）共存；团长**仅在后台配置**，小程序不提供自助申请入口。
- **商城商品增加分销佣金**：SKU 新增固定分销佣金（分/件）。
- **价格口径**：团长身份用户看/付「SKU 售价」；非团长用户看/付「SKU 售价 + 分销佣金」。
- **佣金归属**：订单完成后，分销佣金归订单用户的归属团长；无归属团长时并入平台尾差（不单独立账）。

## 二、核心数据

- `mall_sku.distribution_commission`：分销佣金（分/件，固定金额）。
- `user_leader`：用户归属团长关系（user_id 唯一，一个用户最多一个团长；仅后台维护）。
- `split_snapshot.leader_amount`：团长分销佣金额（无团长为 0），便于对账。
- `order_item.distribution_commission`：下单时分销佣金单价快照。
- `orders.split_rule_snapshot` JSON 内追加 `leaderSubjectId / leaderUserId`：下单时归属团长快照。

迁移文件：`server/src/main/resources/db/migration/V87__mall_leader_distribution.sql`。

## 三、角色与后台

- 团长 = `biz_subject(subject_type='LEADER')` + `user_role_grant(role_code='LEADER')`，不覆盖 `app_user.bound_subject_id / business_role`，因此可与其他经营角色共存。
- 后台入口：
  - `POST /api/v1/admin/subject/leaders`（把用户设为团长）
  - `DELETE /api/v1/admin/subject/leaders/{subjectId}`（解除团长）
  - `GET /api/v1/admin/subject/leaders`（团长列表）
  - `POST /api/v1/admin/user-leader`（为用户指定归属团长）
  - `DELETE /api/v1/admin/user-leader/{userId}`（移除归属）
  - `GET /api/v1/admin/user-leader`（归属列表）
- 用户列表页新增「团长」绑定类型、「归属团长/取消归属」操作与团长身份展示。
- 小程序「角色中心」会展示团长卡片（图标复用 Lucide users），可切换身份；但 `/api/v1/app/roles/apply` 明确拒绝 leader 申请。

## 四、分账口径

- 商城订单（`OrderVerifiedEvent.mallOrder=true`）：门店提成恒为 0。
- 分销佣金合计 = Σ(分销佣金单价 × 件数)。
- 有归属团长 → 佣金计入团长主体（LEADER）可用余额，settlement_record 记一笔「团长分销佣金」。
- 无归属团长 → 佣金并入平台尾差，不单独立账。
- 供应商成本、投资人、平台提成逻辑不变；守恒校验包含团长份额（平台+门店+资源方+投资人+供应商+团长=实付）。
- 团长身份用户购买：售价结算、佣金不外分（以团长身份为准）。

## 六、部署提示

- 上线前执行 V87 迁移（幂等）。
- 商城 SKU 需由运营在后台配置「分销佣金」；未配置（0）时价格与非团长展示一致，不影响下单。
- 团长与归属关系为纯后台配置；小程序无需发布新申请入口。
- 真实 MySQL 迁移与真机支付/分账联调需按部署手册在上线环境完成。
