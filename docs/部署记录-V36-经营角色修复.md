# 经营角色绑定/解绑修复 · 部署记录（V36）

> 日期：2026-09-25
> 触发：用户反馈「经营角色不是解绑了么，怎么还显示数据？并且还有英文的信息（STORE）」
> 状态：✅ 已上线并验证

---

## 一、问题根因（三个现象，两个真 Bug + 一个读侧映射缺失）

| # | 现象 | 根因 | 性质 |
|---|------|------|------|
| 1 | 解绑后数据仍在 | `unbindUserRole` 用 `subjects.find(s => s.code === user.boundSubjectId)` 定位主体；<br>`boundSubjectId` 是**数字 id**（101），`code` 是**字符串**（ST-1001），恒不相等 → subject 恒为 undefined → 在警告后直接 return，**DELETE 请求从未发出** | 真 Bug（功能失效） |
| 2 | 经营角色显示英文 STORE | 库中 `business_role` 大小写混存（`store` / `STORE`），前端映射表用小写 key，大写不命中 → 走 `?? v` 兜底原样输出英文 | 真 Bug（大小写不一致） |
| 3 | 绑定主体列恒为 — | `app_user` 无 `bound_subject_name` 列，后端也不返回该字段；前端未把 `bound_subject_id` 解析成主体名 | 读侧映射缺失 |

**关键结论：数据一直是存进数据库的，是「解绑没发出请求」+「读取没做映射」造成的错觉。**

## 六、回滚步骤

```bash
# 1. 回滚数据库（V36 是数据归并，无 DDL，回滚只需恢复数据）
docker exec -i wuling-mysql mysql -uwuling -p$PW wuling < /opt/wuling/backup/v36-pre-20260925-135916.sql

# 2. 回滚后端
cd /opt/wuling/build
cp server/target/server.jar.bak-v36-20260925-140529 server/target/server-0.1.0-SNAPSHOT.jar
docker tag wuling/server:20260925-095629 wuling/server:local
docker compose -f docker-compose.prod.yml --project-name wuling up -d --force-recreate --no-deps server

# 3. 回滚前端
rm -rf /opt/wuling/web && mv /opt/wuling/web.old-v36-20260925-140752 /opt/wuling/web
systemctl reload nginx
```

> 注意：Flyway 已记录 V32–V36，回滚数据库后若再启动新版后端，Flyway 会认为已执行而跳过 ——
> 此时需同时回滚后端镜像/jar（回到 V31 版本）才能保持版本一致。
