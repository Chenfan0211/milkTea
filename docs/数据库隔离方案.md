# 数据库隔离方案

> 日期：2026-09-22
> 背景：**第 0 期生产事故的根因** —— 本地开发经 SSH 隧道直连生产 MySQL，
> 导致 Flyway 迁移（V11/V12/V13）被误应用到生产库。

---

## 一、问题回顾

### 1.1 事故经过

| 时间 | 事件 |
|------|------|
| 09-22 02:19 | 本地开发跑第 0 期迁移，**实际写入生产库**（V11/V12） |
| 09-22 10:19 | 本地开发跑 P2 迁移，**再次写入生产库**（V13） |
| 09-22 11:26 | 生产加固重启服务，Flyway 校验失败，**服务中断 18 分钟** |

### 1.2 根因

```yaml
# application-dev.yml（问题所在）
url: jdbc:mysql://127.0.0.1:13306/wuling   # 经 SSH 隧道 -L 13306:生产3306
```

本地 `13306` 实际指向**生产 MySQL**。开发者的每一次 `mvn spring-boot:run`、
每一次 Flyway 自动迁移，都直接作用于生产数据。

### 1.3 同类问题（第 4 期再次复现）

| 共用项 | 后果 |
|--------|------|
| MySQL（13306 隧道） | 误迁移生产库 |
| Nacos（18848 隧道） | 服务发现互相污染，网关路由 1/3 超时 |
| Redis（16379 隧道） | 生产轮换口令后本地全部失效 |

> 结论：**开发与生产共用基础设施**是系统性风险，必须逐个切断。

---

## 二、隔离方案（三层防护）

### 第一层：数据库强制只读 ⭐ 最关键

在生产库创建**只读账号** `wuling_ro`，开发环境使用该账号。

```sql
CREATE USER 'wuling_ro'@'%' IDENTIFIED BY '<随机口令>';
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'wuling_ro'@'%';
GRANT SELECT ON wuling.* TO 'wuling_ro'@'%';
FLUSH PRIVILEGES;
```

**为什么这是关键**：即使开发者误跑迁移、误调写接口，
**MySQL 会在协议层直接拒绝**，不依赖任何人的自觉。

**已验证**（通过应用同款 JDBC 路径）：

| 操作 | 结果 |
|------|------|
| `SELECT` | ✅ 成功（orders = 14 行） |
| `UPDATE` | ❌ 拒绝 `ERROR 1142 UPDATE command denied` |
| `CREATE TABLE` | ❌ 拒绝 `ERROR 1142 CREATE command denied` |

### 第二层：关闭 dev 的 Flyway

```yaml
# application-dev.yml
spring:
  flyway:
    enabled: false    # 迁移统一由生产部署执行
```

避免本地启动时尝试执行迁移（本地库不存在会失败；连生产则会报错）。

### 第三层：启动守卫提示

新增 `DevDataSourceGuard`（仅 `@Profile("dev")` 生效）：

- 启动完成后检查数据源 URL
- 若指向疑似生产地址（`172.16.0.16` / `43.136.91.239` / `wulingshiguang.top`），打印**醒目警告**
- 若使用可写账号 `wuling`，额外警告应改用 `wuling_ro`

```
⚠ 开发环境正在连接【生产数据库】: jdbc:mysql://127.0.0.1:13306/wuling
  当前账号: wuling_ro
  请确认该账号为只读账号(wuling_ro)，否则可能误改生产数据！
```

## 三、配置变更

### 3.1 `application-dev.yml`（server / auth-service）

```yaml
spring:
  flyway:
    enabled: false            # 第二层：本地不跑迁移
  datasource:
    url: jdbc:mysql://127.0.0.1:13306/wuling?...
    username: ${MYSQL_USER:wuling_ro}   # 第一层：默认只读账号
    password: ${MYSQL_PASSWORD:}
```

### 3.2 本地环境变量

口令不入仓库，放 `.env.local.properties`（已在 `.gitignore`）：

```
MYSQL_USER=wuling_ro
MYSQL_PASSWORD=<只读账号口令>
REDIS_PASSWORD=<生产 Redis 口令>
RABBITMQ_PASSWORD=<生产 MQ 口令>
```

## 四、终极方案：本地独立库（待执行）

当前方案是**止血**（限制权限），不是真正隔离。
彻底方案是在本地起独立 MySQL：

### 4.1 准备数据快照

```bash
# 在服务器执行：仅导出结构与种子数据（不含订单/用户等业务数据）
bash /opt/wuling/scripts/export-dev-db.sh /opt/wuling/backup/dev
```

脚本产出三个文件：
- `schema-*.sql` —— 全部表结构（含存储过程、触发器）
- `seed-*.sql` —— 字典/商品/门店等**基础数据**（排除业务数据）
- `flyway-*.sql` —— Flyway 历史（保证版本一致）

### 4.2 本地一键搭建

```powershell
# 前置：安装 Docker Desktop
.\scripts\setup-local-db.ps1 -DumpDir E:\backup\dev
```

脚本会：
1. 启动独立 MySQL 8 容器（端口 `13307`，避开隧道的 `13306`）
2. 导入结构 + 种子 + Flyway 历史
3. 输出需更新的配置项

### 4.3 切换配置

```yaml
url: jdbc:mysql://127.0.0.1:13307/wuling?...
username: root
flyway:
  enabled: true     # 本地库可自由迁移
```

> ⚠️ 本机当前**未启用 WSL**（`WSL_E_OPTIONAL_COMPONENT_REQUIRED`，需重启安装），
> 也**未安装 Docker**，因此该步骤待环境就绪后执行。

## 五、Nacos 隔离（第 4 期已完成）

```yaml
# 各服务 application-dev.yml
spring:
  cloud:
    nacos:
      discovery:
        enabled: false     # 本地不注册，避免污染生产注册表
```

网关 dev 改用**静态路由**指向本地端口。

**效果**：修复前经网关约 1/3 超时 → 修复后 **10/10 成功**。

## 七、剩余风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 本地仍可**读**生产数据 | 只读账号能查全部业务数据 | 改用本地独立库（第四节） |
| 隧道中断导致本地不可用 | SSH 隧道超时断开 | 已加 `ServerAliveInterval=30` 保活 |
| 生产 Redis 被本地共用 | 本地读写生产 Redis（如登录限流计数） | 后续可加 Redis 逻辑库或独立实例 |

> **强烈建议**：环境允许时尽快执行第四节，用本地独立库替代只读连生产。
