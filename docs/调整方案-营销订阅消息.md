# 调整方案：营销订阅消息（系统门店取值版）

> 日期：2026-10-22
> 状态：代码已实施，待部署与微信真机复验

## 目标

- 在保留“下单成功”订阅消息的基础上，新增 6 个营销订阅模板。
- 订阅授权采用一次性订阅：业务动作只申请该动作主模板，“我的-消息订阅”页面以单列表展示 7 项通知及真实微信状态，每项独立开启或跳设置关闭。
- 所有带“门店名称”的模板均从系统主体表 `biz_subject.name` 读取，前端只传 `storeSubjectId`。
- 找不到有效门店时只跳过该条通知，不影响签到、充值、支付、退款等业务。

## 门店取值

- 签到：`POST /api/v1/app/points/signin?storeSubjectId=`
- 储值充值：`POST /api/v1/app/stored-value/orders?packageId=&storeSubjectId=`，订单持久化 `store_subject_id`
- 订单消费积分、邀请积分：`OrderPaidEvent.storeSubjectId`
- 余额支付、退款：trade 调用余额内部接口时携带 `storeSubjectId`
- 后端按 `biz_subject.id` 查询 `subject_type='STORE'`、`status='active'`、`deleted=0` 的名称；无效则不发送带门店字段的通知。

## 小程序

- `user-h5/utils/subscribe-message.js`：统一模板 ID、单列表状态读取、单模板开启和上下文授权。
- 原自定义 `pages/subscribe-message` 单列表方案已废弃并删除；当前仅按业务场景调用微信原生 `requestSubscribeMessage` 授权。
- “我的”页功能宫格按产品要求隐藏“消息订阅”入口；订阅页面代码保留，但不再从 `profile_functions` 展示入口。
- 业务内只补主模板：签到、积分兑换、储值充值；下单继续沿用原订单订阅。

## 后端

- `marketing-service` 新增订阅发送模块、access_token 提供器、微信发送客户端、事务提交后通知器、独立有界线程池和优惠券到期任务。
- 新增 `subscribe_message_log` 发送幂等账本。
- 新增 `user_coupon.grant_no`，普通渠道固定 `SINGLE`；储值赠券使用 `SV:{orderNo}:{couponId}:{index}`，支持多张且重复回调不重复入账。
- 储值套餐赠券在 `markPaid` 同一事务内发放；库存不足只跳过赠券并记 WARN，不阻断充值。
- access_token 复用 Redis 键 `wuling:cache:wx:miniapp:access_token:{appId}`。

## 迁移与部署

- Flyway：V81 初始化订阅能力，V82 从 `app_config.profile_functions` 移除消息订阅入口。
- 部署顺序：`server` → `marketing-service` → `user-h5`。
- 生产环境复用 `WX_APP_ID / WX_APP_SECRET`；模板 ID 与开关见 `deploy/wechat-pay-secrets.env.example`。
- 急停：设置 `WX_MARKETING_SUBSCRIBE_ENABLED=false` 并重启 `marketing-service`。

## 我的页入口移除与缓存失效

V82 直接更新 `app_config`，不会主动清理 Redis 配置缓存；`/api/v1/app/config/profile` 的缓存键为：

`wuling:cache:app_config:profile_functions`

部署 `server` 并执行 V82 后，必须按生产实际缓存库（默认 db 2）删除该键：

```bash
docker exec wuling-redis redis-cli -a "$REDIS_PASSWORD" -n 2 DEL wuling:cache:app_config:profile_functions
```

随后校验数据库与接口：

```sql
SELECT config_key, status, deleted,
       JSON_CONTAINS(value, JSON_OBJECT('id', 'subscribe-message')) AS has_subscribe_entry
FROM app_config
WHERE config_key = 'profile_functions';
```

预期 `has_subscribe_entry=0`，且“我的”页不再展示“消息订阅”入口。若缓存未清理，旧的入口配置可能继续存在直到 TTL 到期。

## 原生授权 + 持久队列改造（2026-10-22 最终版）

- 小程序按业务场景发起原生授权：签到 `[积分变更]`，兑换 `[积分兑换, 积分变更]`，充值 `[储值充值, 余额变动, 优惠券到账]`；不再提供自定义开关页。
- marketing-service 的 6 类营销通知全部改为事务内 `event_outbox`，路由到 `wuling.subscribe.marketing.queue`，微信发送只发生在消费者侧。
- 消费者复用 `subscribe_message_log` 账本并采用成功后再幂等的消费模式；短暂微信异常走延迟重试，超限进入 `wuling.subscribe.marketing.queue.dlq`。
- 优惠券到期任务在事务内登记 outbox，任一入队失败整批回滚，下一次调度可安全重试。
- DLQ 已纳入 `DlqMonitor.MONITORED`；回滚时停止消费者，保留队列和 outbox，不执行清空操作。
